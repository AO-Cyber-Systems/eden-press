<objective>
Resolve the single blocking cross-package gap this whole objective sits on (research Pitfall 4 / Open Question 1): `press.Options` has NO hook for injecting caller-supplied theme CSS, so CLI-05 `--theme-set` cannot be built as a CLI-only feature without violating the "CLI imports only press/" boundary. Close it with a small, PURELY ADDITIVE extension to the Objective-3-frozen API surface:

1. `press.Options.ThemeCSS []string` — raw theme-CSS text the caller supplies; `press.Render` registers each via the exact `chase/theme.Load` + `ThemeSet.Add` path the embedded themes use. press/ never reads the filesystem (keeps `Render` a pure function of `(md, opts)`).
2. `press.BrowserFitJS() string` — a package-root re-export of `press/themes.BrowserFitJS()`, so the CLI can splice the auto-fit helper while importing ONLY `press`.

Purpose: this is the Wave-0 blocker the research flags as the highest-leverage decision in the objective. It touches a package Objective 3 shipped/merged, so it MUST stay additive (zero value = today's behavior) to avoid breaking Objective 7's parallel Options-serialization workstream. Sequenced first so 04-05 (`--theme-set`) and 04-03 (`--auto-fit-script`) have their press/ seams before they are planned to consume them.
Output: `press.Options.ThemeCSS` threaded into `packThemeCSS`, plus the `press.BrowserFitJS` re-export — both additive, both test-fenced.
</objective>
