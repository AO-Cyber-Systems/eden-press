<objective>
Deliver CLI-02: watch mode. `eden-press watch <in.md>` rebuilds the output whenever the source changes, and (via a stdlib SSE reload channel) tells an open browser to refresh. Build it on fsnotify's documented-correct pattern — watch the PARENT DIRECTORY, filter by name, survive atomic-save renames, ignore Chmod/backup/swap noise, debounce ~300ms — and re-use 04-03's render pipeline + script-injection seam rather than reinventing either. The SSE reload package built here is the shared plumbing serve (04-07) reuses.

Purpose: CLI-02 is where fsnotify's real sharp edges live (Pitfalls 2/6/8). The correctness bar is: works after the first save AND every save (atomic-rename-safe), one rebuild per logical save (debounce), and no rebuild storm on directory noise. The reload channel is deliberately SSE (unidirectional server→browser), stdlib-only, `EventSource` auto-reconnecting — no websocket dependency (research Pattern 4).
Output: `watch.go` (scoped, debounced, atomic-save-safe watcher) + `cmd/eden-press/reload` (SSE server + embedded EventSource client) wired through 04-03's seams.
</objective>

fsnotify parent-directory watch (research Pattern 3 / Pitfall 2 — NEVER watch the file directly):
```go
// cmd/eden-press/watch.go
func runWatch(cmd *cobra.Command, args []string) error {
    arg := "-"; if len(args) == 1 { arg = args[0] }
    if arg == "-" { return fmt.Errorf("watch: cannot watch stdin (\"-\"); pass a file path") } // Pitfall 8
    absIn, _ := filepath.Abs(arg)
    dir := filepath.Dir(absIn)
    w, err := fsnotify.NewWatcher(); if err != nil { return err }
    defer w.Close()
    if err := w.Add(dir); err != nil { return err } // watch the DIR, filter by name
    rebuild := debounced(300*time.Millisecond, func() { rebuildOnce(cmd, absIn, reloadHub) })
    rebuildOnce(cmd, absIn, reloadHub) // initial build
    for {
        select {
        case ev := <-w.Events:
            if filepath.Clean(ev.Name) != absIn { continue }         // only OUR file
            if ev.Op&fsnotify.Chmod != 0 { continue }                // ignore Chmod (spurious)
            if isBackupOrSwap(ev.Name) { continue }                  // ~ / .swp editor noise
            rebuild()                                                // atomic rename fires Create/Rename on absIn → caught here
        case err := <-w.Errors:
            fmt.Fprintln(cmd.ErrOrStderr(), "watch:", err)
        }
    }
}
```
Debounce (research Pattern 3 — one rebuild per quiet period):
```go
func debounced(d time.Duration, fn func()) func() {
    var mu sync.Mutex; var t *time.Timer
    return func() { mu.Lock(); defer mu.Unlock(); if t != nil { t.Stop() }; t = time.AfterFunc(d, fn) }
}
```
rebuildOnce reuses 04-03's pipeline + splices the reload client via the InjectScripts seam:
```go
func rebuildOnce(cmd *cobra.Command, path string, hub *reload.Hub) {
    md, _, err := resolveInput(path); if err != nil { /* log, keep watching */ return }
    opts, _ := buildOptions(cmd)
    out, err := press.Render(md, opts); if err != nil { /* log, keep watching */ return }
    doc := assembleHTML(out, htmlDocOptions{
        AutoFitScript: cfg.Bool("auto-fit-script"),
        InjectScripts: []string{reload.ClientJS(hub.URL())}, // SSE EventSource snippet — watch-session only
    })
    writeWatchOutput(cmd, path, doc) // default <stem>.html
    hub.Broadcast("reload")
}
```
SSE server (research Pattern 4 — stdlib only, no websocket):
```go
// cmd/eden-press/reload/server.go
func (h *Hub) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "text/event-stream")
    w.Header().Set("Cache-Control", "no-cache")
    ch := h.subscribe(); defer h.unsubscribe(ch)
    rc := http.NewResponseController(w)
    for msg := range ch {
        fmt.Fprintf(w, "event: %s\ndata: %s\n\n", msg, msg)
        rc.Flush()
    }
}
```

<anti_patterns>
- Do NOT watch the markdown file directly — watch its parent dir and filter by name, or atomic-save renames silently kill the watch after the first edit (Pitfall 2, the classic Vim bug).
- Do NOT rebuild on every raw event — editors fire several per save; debounce (~300ms) so one save = one rebuild (Pitfall 3 / Pattern 3).
- Do NOT feed the reload `<script>` through press.Render — splice it via 04-03's InjectScripts seam, after out.HTML (the sanitizer strips `<script>`).
- Do NOT build a websocket reload channel — SSE (unidirectional, stdlib, EventSource auto-reconnect) is the chosen mechanism (Pattern 4); adding a websocket dep is scope creep.
- Do NOT walk the whole repo recursively — v1 scope is the input-file (+ theme-set) dir only; recursive is a documented later config option (Pitfall 6 / Open Question 3).
- Do NOT reject Chmod as an error or treat directory `Write` as a content change — filter both (cross-platform semantics differ).
- Do NOT default any port to 8080 — the reload endpoint binds loopback on a non-8080 port; local verification uses 8091.
</anti_patterns>

<error_recovery>
- If watch stops rebuilding after one save, the code watched the file (not the dir) or didn't re-match `Event.Name` after a rename — switch to parent-dir watch + name filter (Pitfall 2).
- If multiple rebuilds fire per save, the debounce timer isn't resetting (each event must `Stop` + reschedule the single shared timer).
- If the browser never reloads, the SSE endpoint URL in client.js doesn't match hub.URL(), or Flush isn't called after each write — use http.NewResponseController(w).Flush() (or http.Flusher) per event.
- Testing fsnotify deterministically is hard; unit-test the pure pieces (debounce, isBackupOrSwap, the name filter, the SSE hub broadcast via httptest) and keep the end-to-end file-change test tolerant (poll for output change with a timeout), documenting per-OS manual verification (macOS now; Linux/Windows tracked, research riskiest-item #2).
</error_recovery>
