<objective>
Ship `profiles/slides` as profile #1 (the ONLY registered Profile impl) AND de-hardcode the slide-specific assumptions out of `chase/theme` — the anti-pattern research flagged HARDEST. This is the single most consequential architectural act of the whole project: doing it NOW (while chase/theme is young, before Objective 3 hardens the public API) is what keeps `profiles/paged`/`article`/`epub` additive instead of a rewrite.

Purpose: Realize differentiator #1. The scoping ALGORITHMS/passes stay in chase/theme (profile-agnostic); only the concrete profile-VARYING VALUES move to profiles/slides — the unit-element selector (`section`), the size table (16:9/4:3 + default 1280x720), the slide-reset scaffold CSS, and the pagination rule. The behavior-preserving invariant is the Objective-1 cssdiff + corpus gates staying green.
Output: `profiles/slides` package (implements profile.Profile, self-registers) + a de-hardcoded `chase/theme` that is grep-clean of slide assumptions.

SCOPE NOTE (read before starting): the grep gate targets chase/model + chase/theme ONLY. chase/markdown legitimately keeps emitting `.marpit`/`<section>` (Marpit container mechanic, out of grep scope, shipped in Objective 1) — do NOT rewrite chase/markdown here. The move is VALUE relocation + parameter threading, backed by the cssdiff/corpus safety net — NOT a rewrite of the scoping algorithm.
</objective>

<codebase_examples>
The de-hardcoding is surgical because the plumbing is ALREADY parameter-shaped — `pack.go` already threads `container`/`slide` chains into the scope pass; the values just need to come from the CALLER instead of hardcoded chase/theme helpers:

```go
// chase/theme/pack.go (on main) — TODAY the slide values are hardcoded here:
container := selector.NonSVGContainerChain()          // "div.marpit"
if opts.InlineSVG { container = selector.InlineSVGContainerChain() }
slide := selector.SlideChain()                        // "section"  ← HARDCODED
...
passes := []Pass{scaffoldPass(ts.scaffold.Sheet.Rules, skipScaffold)}   // scaffold ← HARDCODED
...
scopePass(container, slide),                           // already a param — just change the source of `slide`
```

The deep bake is the `:root` specificity trick, which fuses on the literal ident `"section"`:
```go
// chase/theme/selector/scope.go (on main):
var slideChain = mustParseTokens("section")           // ← relocate the "section" literal to profiles/slides
func SlideChain() []css.Token { return slideChain }   // ← rename UnitChain; caller supplies the ident
// Prepend() fuses when: compound[0] == IdentToken "section"   ← parameterize this ident
// pass_root.go emits the literal text "section:marpit-root"    ← emit "{unit}:marpit-root"
```

The size table + defaults (relocate to profiles/slides, pass in as params):
```go
// chase/theme/meta.go:      bareSizeFallback = {"4:3":960x720, "16:9":1280x720}
// chase/theme/stylesheet.go: defaultWidthPx=1280, defaultHeightPx=720  (keep the generic `Size` struct)
```

profiles/slides then OWNS these values and hands them to theme via the Profile (the entrypoint in 02-04 bridges):
```go
// profiles/slides/slides.go (new):
func (p slides) UnitElement() string { return "section" }
func (p slides) Sizes() profile.SizeTable {
    return profile.SizeTable{
        ByName:  map[string]theme.Size{"16:9": {"16:9",1280,720}, "4:3": {"4:3",960,720}},
        Default: theme.Size{"16:9",1280,720},
    }
}
func (p slides) Scaffold(inlineSVG bool) string { /* moved slide-reset (+ advanced-bg) CSS */ }
func init() { profile.Register(slides{}) }
```

<anti_patterns>
- ANTI-PATTERN 1 (ARCHITECTURE.md, the one research flags HARDEST): hardcoding `section`/`16:9`/`Slide` inside the scoping engine. This TRD's entire job is to REMOVE it from chase/theme. After this TRD, adding a paged profile (`.page` container, A4/Letter sizes, no `section` reset) must require ZERO chase/theme edits.
- Do NOT rewrite the scoping passes themselves — they are shared/profile-agnostic and MUST stay in chase/theme (ARCHITECTURE.md Pattern 2: "chase/theme's scoping passes themselves" are shared). Only relocate VALUES and thread them as params.
- Do NOT create an import cycle: chase/theme must NOT import chase/profile or profiles/slides. Pass primitives / chase/theme value types. The Profile→theme edge is one-way.
- Do NOT rewrite chase/markdown's `<section>`/`.marpit` emission — it is out of the grep scope and shipped in Objective 1. Touching it risks the corpus gate for no grep benefit.
- Do NOT "fix" the cssdiff fixtures to make them pass — if a fixture goes red, the de-hardcoding changed BEHAVIOR (a bug). Make slides supply the exact same values that were hardcoded, so the fixtures pass UNCHANGED.
</anti_patterns>

<error_recovery>
- If the cssdiff gate (`chase/theme/pack_conformance_test.go`) or corpus gate (`conformance/runner/chase_corpus_test.go`) goes red after a move: the relocation was not value-identical. Diff the packed CSS; the usual cause is the unit ident, the scaffold text, or the pagination rule differing by a byte. Restore byte-parity — do NOT edit the golden fixtures.
- If parameterizing the Prepend fused-element ident is intricate (it fuses on `compound[0].Data == "section"`): keep the fusion ALGORITHM identical, just compare against the passed `unitIdent` instead of the literal. pass_root.go's `MarkRoot` emitting `"{unit}:marpit-root"` must stay consistent with that fused ident so the `:root` trick still resolves.
- If bottom-up validation shows profile.Profile (02-02) is missing/mis-shaped a method for a real theme.Pack call-site, refine chase/profile/profile.go here (sequential wave — allowed) and note it in the SUMMARY.
- Commit in this order so the build never breaks mid-move: (1) add profiles/slides supplying the values; (2) thread params into chase/theme with slides supplying identical values, re-green gates; (3) grep gate. Each commit is GREEN before the next.
