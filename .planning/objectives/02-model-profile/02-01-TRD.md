<objective>
Ship `chase/model`: Eden Press's own versioned, JSON-serializable document model built by a DIRECT recursive walk of the finalized goldmark AST that `chase/markdown` already produces. This is differentiator #3 ("output-as-data") made a first-class package on day one — `Document{Meta, Sections, Outline}` where a "Section" is the generic unit a profile happens to call a slide (never a `Slide` type).

Purpose: The docmodel is the product; goldmark's `ast.Node` tree is a transient parse-time structure (segment-based text, no JSON, version-unstable shape). A consumer (Eden-Biz, AOCore, an LLM ingestion pipeline) must get outline/notes/metadata WITHOUT parsing HTML back out of HTML.
Output: `chase/model` package with `Document`/`Section`/`Meta`/`Outline` types + `Build()` + tests, importable independently (chase/* is EXPORTED — see 02-02).
</objective>

The top-level children of that finalized `*ast.Document` are `*markdown.Section` nodes (one per slide). Each Section already carries its resolved directive attributes:

```go
// chase/markdown/section.go (on main):
var KindSection = ast.NewNodeKind("MarpitSection")
type Attr struct{ Name, Value string }   // ordered — declaration order is significant
type Section struct {
    ast.BaseBlock
    ID    int      // 1-based slide index
    Attrs []Attr   // data-*/style/class/lang directive attrs (populated by apply.go)
}

// chase/markdown/section.go — comments carry raw + recognized KV; Hidden==true:
var KindCommentNode = ast.NewNodeKind("MarpitComment")
type CommentNode struct {
    ast.BaseBlock
    Raw    string             // trimmed inner body between <!-- and -->
    KV     map[string]string  // raw key/value pairs (empty for a plain note)
    Hidden bool
}
// CommentInline (KindCommentInline) is the inline sibling — same fields.
```

Slug ids for headings are already present: the engine runs `parser.WithAutoHeadingID()` (seam.go `NewEngine`), so each `*ast.Heading` has an `id` attribute available via `n.Attribute([]byte("id"))`. Extract heading text with goldmark's segment API: `n.Text(source)` / iterate `n.Lines()` and `seg.Value(source)` — materialize into OWNED strings (never hold a `text.Segment` past the walk).

Walk pattern (mirror Pattern 3 in ARCHITECTURE.md):
```go
func Build(doc ast.Node, source []byte, pc parser.Context) *Document {
    d := &Document{SchemaVersion: SchemaVersion, Meta: buildMeta(pc)}
    for n := doc.FirstChild(); n != nil; n = n.NextSibling() {
        if sec, ok := n.(*markdown.Section); ok {
            d.Sections = append(d.Sections, buildSection(sec, source))
        }
    }
    d.Outline = buildOutline(d.Sections)
    return d
}
```
Deck-level Meta comes from the resolved front-matter directive state in `pc` (see `chase/directive` — `FrontMatterKey` and the CoerceGlobal-resolved values apply.go reads); reuse those, don't re-derive from HTML.

<anti_patterns>
- ANTI-PATTERN 1 (research flagged hardest): do NOT name anything `Slide`, and do NOT hardcode `section`/`16:9`/`720` in `chase/model`. The type is `Section`; "a Section is what a profile happens to call a slide or a page" (ARCHITECTURE.md line 154). This package must stay profile-agnostic — grep-verified in 02-03.
- Do NOT call `goldmark.Convert()` or re-parse the source to build the model — that forces either a second parse (fidelity/perf risk) or reverse-engineering structure from HTML (fragile/lossy). Walk the SAME finalized doc `markdown.Parse` returns (ANTI-PATTERN 2/3 in ARCHITECTURE.md).
- Do NOT hold `text.Segment` values in the model — they index into the source buffer. Materialize to owned `string` during the walk (goldmark's ast is a transient working structure; the docmodel is the durable product).
- Do NOT mutate the AST during Build. Build is read-only; a later objective renders HTML from the same doc and must see it unchanged.
</anti_patterns>

<error_recovery>
- If a heading has no `id` attribute (AutoHeadingID edge case, e.g. empty heading), fall back to an empty slug string rather than panicking on the nil attribute — `n.Attribute` returns `(nil, false)`.
- Speaker-note vs directive-comment disambiguation: a `*markdown.CommentNode` whose KV resolved to a recognized directive is applied to the Section as attrs by `apply.go`; a comment that is NOT a recognized directive is a note. Discriminate by consulting the resolved-directive keys (the same set apply.go used), NOT by re-parsing `Raw`. If in doubt, prefer treating a comment with an empty/unrecognized KV as a note.
- Empty deck (no `*Section` children): return a `*Document` with `Sections: nil`, `Outline: nil`, populated `Meta` and `SchemaVersion` — never nil the whole Document.
</error_recovery>

## Test list

Write the test list FIRST, then drive each case RED → GREEN (one test at a time; hand-built inline fixtures — no generated test data). Order outermost (whole-Document shape) → innermost (single field).

1. `Build` on a 3-slide deck → `len(Document.Sections) == 3`, each Section's `ID` matches its 1-based index.
2. Deck with `# H1` / `## H2` headings → `Document.Outline` lists each heading with correct `Level`, materialized `Text`, and AutoHeadingID `Slug`, in document order and grouped under the owning slide.
3. Slide containing `<!-- just a presenter note -->` → that text appears in the owning Section's `Notes`; a recognized directive comment (`<!-- paginate: true -->`) does NOT appear in `Notes`.
4. Deck with front matter (`theme: gaia`, `size: 16:9`, `class: lead`) → `Document.Meta` carries those resolved values.
5. `json.Marshal(doc)` then `json.Unmarshal` round-trips to an equal Document; the marshaled bytes contain `"schemaVersion"` with the constant value.
6. NON-MUTATION invariant: dump the finalized AST to a string, call `Build`, dump again → identical; AND `markdown.Render(md, nil)` returns byte-identical HTML before vs. after a `Build` call on a parsed doc.
7. Empty document (`""`) → `Document` with nil Sections/Outline but populated Meta + SchemaVersion (no panic).
