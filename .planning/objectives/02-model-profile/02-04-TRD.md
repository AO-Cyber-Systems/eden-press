The two-phase seam already exposes the finalized doc; the ONLY missing piece is rendering a doc you already parsed (today's `markdown.Render` re-parses internally — unusable for a single-parse guarantee):

```go
// chase/markdown/seam.go (on main):
func Parse(md string) (*ast.Document, parser.Context)          // Phase 1 — finalized doc
func Render(md string, opts map[string]any) (string, error) {  // Phase 2 — but RE-PARSES:
    doc, _ := Parse(md)                                        // ← second parse; NOT what the entrypoint uses
    // defaultEngine.Renderer().Render(&buf, source, doc)
}
var defaultEngine = NewEngine()   // unexported — RenderDoc must live in-package to reach it
```

Add `RenderDoc` in chase/markdown so the entrypoint renders the SAME doc Build walked:
```go
// chase/markdown/renderdoc.go (new):
func RenderDoc(doc *ast.Document, source []byte) (string, error) {
    var buf bytes.Buffer
    if err := defaultEngine.Renderer().Render(&buf, source, doc); err != nil { return "", err }
    return buf.String(), nil
}
```

The entrypoint (Pattern 1 / Pattern 3 in ARCHITECTURE.md — adapted: no press/ yet, profile from the registry):
```go
// chase/chase.go (new):
type Output struct {
    HTML  string
    CSS   string
    Model *model.Document
    Meta  model.Meta
}
func Render(md string) (Output, error) {
    p := profile.Default()                       // profiles/slides (only registered)
    source := []byte(md)
    doc, pc := markdown.Parse(md)                // ★ ONE parse
    html, err := markdown.RenderDoc(doc, source) // sink 1
    if err != nil { return Output{}, err }
    m := model.Build(doc, source, pc)            // sink 2 — SAME doc
    css, err := packCSS(p, pc)                   // chase/theme.Pack parameterized by p
    if err != nil { return Output{}, err }
    return Output{HTML: html, CSS: css, Model: m, Meta: m.Meta}, nil
}
```
`packCSS` bridges the Profile → theme.Pack params (unit element, size table, scaffold) the 02-03 refactor introduced — this is where profile → primitives happens, keeping chase/theme free of any chase/profile import.
</codebase_examples>

<anti_patterns>
- ANTI-PATTERN 2 (ARCHITECTURE.md): do NOT use `goldmark.Convert()` or call `markdown.Parse` twice. The whole point is ONE parse feeding two sinks. If you find yourself parsing to get HTML and parsing again to get the model, stop — use RenderDoc + Build on the one doc.
- Do NOT return the model from a SEPARATE render call — MODEL-02 explicitly forbids "two separate render calls." One entrypoint, one parse, both outputs.
- Do NOT make this the PUBLIC API — no batteries (emoji/chroma/math/sanitize), no go:embed themes. That is Objective 3. Keep chase.go the thin internal composer.
- Do NOT let chase/theme import chase/profile (still true here) — the profile→primitives bridge lives in chase.go (or a tiny chase-level helper), not in chase/theme.
</anti_patterns>

<error_recovery>
- If `RenderDoc` output differs from `markdown.Render` for the same source, the two-phase seam has an ordering assumption — ensure RenderDoc uses the SAME `defaultEngine` and the doc from `markdown.Parse` (which already ran all ASTTransformers). They must be byte-identical (renderdoc_test.go asserts this).
- Proving "single parse": either (a) structural — assert the entrypoint calls Parse once by construction and both sinks receive the same `*ast.Document` pointer; or (b) instrumented — a test that counts parser invocations. Prefer (a): render html1 from the shared doc, Build on it, render html2 from the SAME doc, assert html1==html2 (Build is non-mutating per 02-01).
- If `profile.Default()` returns nil (slides not registered), ensure `profiles/slides` is imported for its `init()` side-effect (a blank import `_ "…/profiles/slides"` in chase.go, or a normal import used by packCSS).
</error_recovery>
