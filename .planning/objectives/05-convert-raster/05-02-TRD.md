<objective>
Build the SHARED determinism substrate that both raster exporters (05-03 pdf, 05-04 png) fold in exactly once: (1) ComposeCSS/PageCSSInches — pure, unit-tested CSS transforms that kill animations and drive fixed page/viewport sizing; (2) ApplyDeterminism — the ordered CDP recipe (fixed viewport+scale, pinned UTC timezone + en-US locale, reduced-motion) applied to a Session tab before content loads; (3) LoadHTML — the page.SetDocumentContent loader with a document.fonts.ready wait; and (4) the go:embed STIX Two Math OTF + @font-face injection (EXP-04 font provisioning) so exported math renders real glyphs, with the OFL attribution added to NOTICE.

Purpose: "deterministic" for a headless-Chrome pipeline means pixel-diff-under-threshold, not byte-identical (Pitfall C) — and the single biggest lever on that determinism is pinning every source of variance (viewport, timezone, locale, animation state, font rendering) in ONE shared helper the two exporters can't diverge on. This TRD also resolves the research's Open Question #1 (self-contained assets) as a documented contract rather than new asset-inlining scope.
Output: convert/chrome.ComposeCSS + PageCSSInches + ApplyDeterminism + LoadHTML + embedded STIX font + NOTICE update.
</objective>

<codebase_examples>
Session/tab from 05-01: `sess, _ := chrome.New(convert.Options{})`; `tab, cancel := sess.NewTab()`. ApplyDeterminism + LoadHTML both take that `tab` (a chromedp context).

The profiles/slides size table (profiles/slides/slides.go Sizes()) is the source of viewport/page dimensions: 16:9 default = `theme.Size{Name:"16:9", WidthPx:1280, HeightPx:720}`, 4:3 = `{WidthPx:960, HeightPx:720}`. PageCSSInches converts px→in at 96px/in: 1280/96 = 13.333…in, 720/96 = 7.5in.

Verified CDP signatures (05-RESEARCH Code Examples table, pkg.go.dev 2026-07-21):
```
chromedp.EmulateViewport(w, h int64, opts ...EmulateViewportOption) EmulateAction  // + chromedp.EmulateScale(1.0)
emulation.SetTimezoneOverride(timezoneID string).Do(ctx) error                       // e.g. "UTC"
emulation.SetLocaleOverride().WithLocale(locale string).Do(ctx) error                 // e.g. "en-US"
emulation.SetEmulatedMedia().WithMedia("screen").WithFeatures([]*emulation.MediaFeature{{Name:"prefers-reduced-motion", Value:"reduce"}}).Do(ctx) error
page.GetFrameTree().Do(ctx) (*page.FrameTree, error)
page.SetDocumentContent(frameID cdp.FrameID, html string).Do(ctx) error              // needs a prior Navigate("about:blank")
```
Non-first-class CDP calls (SetTimezoneOverride etc.) are invoked inside `chromedp.ActionFunc(func(ctx) error {...})`, chromedp's documented pattern for any method returning multiple values or not wrapped as a first-class Action.

document.fonts.ready wait (05-RESEARCH Pattern 2 item 5, Pitfall B): no chromedp built-in — replicate Puppeteer's idiom by polling/awaiting the JS promise via `chromedp.Evaluate("document.fonts.ready.then(()=>true)", &res, awaitPromise)` (use the EvaluateAsDevTools/awaitPromise option so the promise resolves before the action returns).

<anti_patterns>
- Do NOT load HTML via a data: URL (05-RESEARCH Anti-Patterns) — documented truncation bug silently blanks large decks. Use page.SetDocumentContent.
- Do NOT load HTML via a temp file/file:// — it pulls in the local-file-access security posture Marp CLI gates behind --allow-local-files. Keep convert/ free of any "trust this path" flag.
- Do NOT rely on the theme's own CSS honoring @media(prefers-reduced-motion) — Marp theme CSS does not. Inject the !important animation kill directly (ComposeCSS); keep SetEmulatedMedia only as defense-in-depth.
- Do NOT capture a screenshot/PDF immediately after SetDocumentContent — wait on document.fonts.ready first, or a data-URI font FOUT race produces wrong-glyph output intermittently (Pitfall B).
- Do NOT pull STIX Two Math from Google Fonts' CDN/CSS — its subsetting/chunking has been repeatedly reported to strip the OpenType MATH table, silently reintroducing tofu (Pitfall 6). Bundle the font project's own OTF.
- Do NOT add an asset-inlining pre-pass to convert/ — Open Question #1 is resolved as a documented contract; background-image asset self-containment is the deck author's responsibility in v1, not new convert/ scope.
</anti_patterns>
