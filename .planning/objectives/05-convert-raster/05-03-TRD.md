<objective>

This is why PDF gets its own TRD and its own re-validation discipline (hardened in 05-05), and why "byte-reproducible" is the wrong bar for this path.
Output: convert/pdf.ToPDF + a structural PDF test suite including an inline-SVG fixture.

Verified PrintToPDF surface (05-RESEARCH Pattern 1 + Code Examples, pkg.go.dev 2026-07-21):
```go
// Not a first-class chromedp.Action — returns (data, stream, err), so wrap in ActionFunc:
chromedp.ActionFunc(func(ctx context.Context) error {
    data, _, err := page.PrintToPDF().
        WithPrintBackground(true).     // REQUIRED — theme backgrounds are content
        WithPreferCSSPageSize(true).   // honor the @page size from PageCSSInches
        WithMarginTop(0).WithMarginBottom(0).WithMarginLeft(0).WithMarginRight(0).
        Do(ctx)
    if err != nil { return err }
    /* store data */
    return nil
})
```
There is NO WithFormat("A4") — paper size is CSS-@page-driven (PageCSSInches) + WithPreferCSSPageSize(true). Confirmed builder methods also include WithScale/WithLandscape/WithDisplayHeaderFooter — not needed for fixed-size slides.

Building the full HTML document: press.Output.HTML is a body fragment; wrap it as `<!doctype html><html><head><meta charset="utf-8"><style>` + composed CSS + `</style></head><body>` + out.HTML + `</body></html>`. (The composed CSS already carries the @font-face + animation kill + @page rule.)

Structural PDF assertion without a heavy dependency: a valid PDF starts with the `%PDF-` magic bytes; page count ≈ the count of `/Type /Page` (not `/Pages`) objects in the decompressed stream — for these small fixtures a byte-scan of `/Type/Page` occurrences is a sufficient structural proxy. Prefer counting `/Type /Page` (with optional whitespace) and assert == number of slides in the fixture.

<anti_patterns>
- Do NOT call page.PrintToPDF as a bare chromedp.Action — it returns three values; it MUST be wrapped in chromedp.ActionFunc (05-RESEARCH Pattern 1).
- Do NOT set paper size via WithPaperWidth/Height raw inches as the primary mechanism — use CSS @page + WithPreferCSSPageSize(true) (the fixed-size-deck idiom).
- Do NOT omit WithPrintBackground(true) — Chrome's print pipeline drops background graphics by default, blanking theme colors/backgrounds.
- Do NOT assert byte-identical determinism — Chrome cannot guarantee it (Pitfall C). Assert structural equality (page count + dimensions) + pixel-diff-under-threshold.
- Do NOT re-implement determinism/loading here — call chrome.ApplyDeterminism/LoadHTML/ComposeCSS/PageCSSInches (05-02).
- Do NOT string-diff the inline-SVG fixture as the only check — a foreignObject can render empty in PDF while the HTML string matches (Pitfall 4/A); rasterize + structurally check.
</anti_patterns>
