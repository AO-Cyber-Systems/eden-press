```go
chromedp.Screenshot(sel any, picbuf *[]byte, opts ...QueryOption) QueryAction  // default ByQuery = querySelector
```
Open Question #2 resolution (05-RESEARCH): prefer the simple, individually-verified `chromedp.Screenshot(sel, &buf, chromedp.ByQuery)` in a loop over the slides (one call → one file → one slide) over `ScreenshotNodes` (which stitches a slice of nodes into ONE picbuf — wrong shape for N separate files).

Per-slide selector (profiles/slides Container(), UnitElement()="section"):
- plain mode: container `div.marpit`; slide k selector → `div.marpit > section:nth-of-type(k)` (1-based).
- inline-SVG mode: container `div.marpit > svg > foreignObject`; slide selector → `div.marpit > svg > foreignObject > section` (Open Question #3 — verify Chrome resolves this bounding box correctly).

Slide count comes from out.Model.Sections (len) — the docmodel already carries one Section per slide in document order (chase/model.Document.Sections).

ImageFormat from convert.go (05-01): convert.PNG (default), convert.JPEG. For PNG, chromedp.Screenshot yields PNG bytes directly; for JPEG, decode the PNG buffer and re-encode via image/jpeg (chromedp's CaptureScreenshot WithFormat can also emit jpeg — either is acceptable; keep PNG the default).

<anti_patterns>
- Do NOT use ScreenshotNodes to produce N separate files — it stitches nodes into one buffer (Open Question #2). Loop chromedp.Screenshot per slide.
- Do NOT re-implement determinism/viewport/loading — call chrome.ApplyDeterminism/LoadHTML/ComposeCSS (05-02). The viewport MUST be the fixed deck size (1280×720), pinned via ApplyDeterminism, not host-DPI-dependent.
- Do NOT assume the inline-SVG-mode selector screenshots identically to plain mode — prove it with a smoke test (Open Question #3, Pitfall 4).
- Do NOT skip decoding the output — assert each buffer decodes via image/png and has the expected dimensions (a buffer that's non-empty but wrong-sized is a silent bug).
</anti_patterns>

```go
func ToImages(sess *chrome.Session, out press.Output, opts Options) ([][]byte, error)
```
Flow:
1. Resolve `size` (default 16:9 1280×720; honor out.Model.Meta @size).
2. Compose full self-contained HTML: `<!doctype html>...<style>` + chrome.ComposeCSS(out.CSS) + `</style>...<body>` + out.HTML + `</body></html>`.
3. `tab, cancel := sess.NewTab(); defer cancel()`.
4. `chrome.ApplyDeterminism(tab, size.WidthPx, size.HeightPx)` — this pins the viewport to the fixed deck size.
5. `chrome.LoadHTML(tab, doc)`.
6. Determine slide count = len(out.Model.Sections); determine container from opts.InlineSVG (plain `div.marpit` vs inline-SVG `div.marpit > svg > foreignObject`).
7. Loop k := 1..N: `sel := container + " > section:nth-of-type(" + k + ")"` (for inline-SVG the section is the direct child of foreignObject); `var buf []byte; chromedp.Run(tab, chromedp.Screenshot(sel, &buf, chromedp.ByQuery))`; if opts.Format == convert.JPEG, decode PNG → re-encode JPEG; append buf.
8. return the N buffers.

# GOTCHA: CSS nth-of-type is 1-based; Model.Sections is 0-based → k = i+1.
# GOTCHA: the viewport pin (ApplyDeterminism) is what makes every screenshot exactly 1280×720; do not leave it host-DPI-dependent.

Define the package-local Options (or reuse convert.Options + a Format field): BrowserPath, Format (convert.ImageFormat), InlineSVG bool.
