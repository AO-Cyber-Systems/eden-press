<codebase_examples>
The override mechanism is source-verified (03-RESEARCH.md "CORE-03 exact override mechanism", read directly against goldmark@v1.8.4): goldmark's `renderer.Render()` sorts NodeRenderers ASCENDING by priority then iterates in REVERSE, so the LAST `RegisterFuncs` call for a given `ast.NodeKind` wins, and the LOWEST priority number always registers last → always wins. goldmark's own `StrikethroughHTMLRenderer` registers `ast.KindStrikethrough` (from `github.com/yuin/goldmark/extension/ast`) at priority 500 and emits `<del>`. A custom renderer registered at priority < 500 overrides it. This is the SAME mechanism `chase/markdown`'s own nodeRenderer (priority 0) uses to beat goldmark's DefaultRenderer.

Reference pattern (STACK.md §1 confirmed this exact shape):
```go
package press

import (
    "github.com/yuin/goldmark"
    "github.com/yuin/goldmark/ast"
    extast "github.com/yuin/goldmark/extension/ast"
    "github.com/yuin/goldmark/renderer"
    "github.com/yuin/goldmark/util"
)

type sRenderer struct{}

func (r *sRenderer) RegisterFuncs(reg renderer.NodeRendererFuncRegisterer) {
    reg.Register(extast.KindStrikethrough, r.renderStrike)
}
func (r *sRenderer) renderStrike(w util.BufWriter, source []byte, n ast.Node, entering bool) (ast.WalkStatus, error) {
    if entering { w.WriteString("<s>") } else { w.WriteString("</s>") }
    return ast.WalkContinue, nil
}

// strikethroughOption returns the goldmark.Option press.Render folds into
// NewEngine(pressExtraOpts...). Priority 100 (< 500) beats GFM's <del> renderer.
func strikethroughOption() goldmark.Option {
    return goldmark.WithRendererOptions(
        renderer.WithNodeRenderers(util.Prioritized(&sRenderer{}, 100)),
    )
}
```

`chase/markdown.NewEngine` (seam.go:62) ALREADY bakes in `extension.GFM` (tables+strikethrough+linkify+tasklist), `ghtml.WithHardWraps()`, and `parser.WithAutoHeadingID()`. So tables, hard-breaks, and slugs need NO new option — verify them by building `markdown.NewEngine(strikethroughOption())` and asserting output. <anti_patterns>
- Do NOT register KindStrikethrough at priority ≥ 500 — it would run BEFORE the default and lose the last-write-wins race (research warning sign: "a custom parser never fires / renders as <del>"). Use a number below 500 (100 is safe and matches the STACK.md example).
- Do NOT re-implement tables, hard-breaks, or slugs — they are already in NewEngine. Writing new wiring for them is redundant work and risks double-registration. VERIFY only.
- Do NOT build a full goldmark.Extender when a single WithRendererOptions option suffices — keep the surface minimal and composable into pressExtraOpts.
- Do NOT modify chase/markdown/NewEngine to add the <s> override — press layers it via the extra-options hook, keeping chase's own strikethrough behavior (<del>, GFM-spec-correct) unchanged for chase's own callers.
</anti_patterns>

<error_recovery>
- If the test still sees `<del>`: the priority is ≥ 500 or the wrong KindStrikethrough was imported (must be `github.com/yuin/goldmark/extension/ast`.KindStrikethrough, not a local kind). Verify the import path and priority < 500.
- If AutoHeadingID yields no `id` on a heading (empty-heading edge), that is expected — assert slugs on non-empty headings; an empty heading legitimately has no slug (mirrors chase/model.headingSlug's empty-fallback).
- Slug DEDUP (heading, heading-1, heading-2 for repeats): goldmark's WithAutoHeadingID handles this; if a dedup expectation differs from GitHub's, note it as a documented baseline (FEATURES.md flags dedup as a small detail; do not over-engineer here).
</error_recovery>
