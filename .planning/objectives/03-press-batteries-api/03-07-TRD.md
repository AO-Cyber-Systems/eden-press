Why this is the whole fix (research "Directive plumbing"): `chase/model/build.go`'s `isRecognizedDirectiveKey` (build.go:235) calls `CoerceGlobal(key, "", nil)` to classify a comment as directive-vs-note. Today `<!-- size: 4:3 -->` returns `isKnown=false` → treated as a NOTE (leaks into `Section.Notes`). Adding the two cases makes `isKnown=true` → correctly absorbed as a directive, NOT a note. And `buildMeta` (build.go:167) already materializes ALL front-matter keys (including size/math) onto `Meta.Directives` unconditionally — so front-matter-form size/math already work; only the comment-form classification was broken.

CORE-09 marker emission (research scope note: "a marker/attribute-materialization battery, not a rendering battery"): emit a stable marker for a fitting header (`# <!--fit-->`) and code/math shrink markers, as an ASTTransformer or NodeRenderer added via `press.autofitOption()`. The marker must survive sanitize (co-design with 03-08). `@auto-scaling` is already parsed into theme metadata by `chase/theme/meta.go` (THEME-02, done) and lives in the theme CSS — NO runtime JS. The viewer-side consumer is `themes/browser-fit.js` (embedded in 03-02).

Baseline marker shape (keep simple, Objective-8 hardens): when a heading's inline content contains the literal `<!--fit-->`, strip the marker comment and add a stable attribute/class (e.g. `data-auto-scaling="fit"` or class `fit`) to the heading; wrap fenced-code / math blocks slated for shrink with a stable shrink class. Exact shape is a documented baseline.
