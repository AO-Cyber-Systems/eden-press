<codebase_examples>
`press.Render` mirrors `chase/chase.go`'s one-parse-two-sinks shape (Render + packCSS) but builds a BATTERY-laden engine and adds sanitize + Comments. Do NOT call or modify `chase.Render` — build the sibling directly:

```go
package press

func Render(md string, opts Options) (Output, error) {
    // 1. Resolve profile (registry) + build the battery-laden engine.
    pressExtraOpts := []goldmark.Option{
        strikethroughOption(),           // 03-03
        emojiOption(),                   // 03-04
        highlightOption(opts.HighlightStyle), // 03-05 (omit if opts.NoHighlight)
        math.Option(),                   // 03-06 (respect opts.MathMode)
        autofitOption(),                 // 03-07
    }
    engine := markdown.NewEngine(pressExtraOpts...) // seam.go's extra-options hook

    // 2. THE ONE PARSE.
    source := []byte(md)
    doc, pc := markdown.ParseWithEngine(md, engine) // 03-01 seam — called EXACTLY once

    // 3. Sink 1: HTML via the SAME engine's renderer.
    var buf bytes.Buffer
    if err := engine.Renderer().Render(&buf, source, doc); err != nil { return Output{}, err }
    html := remapHLJS(buf.String())   // 03-05 chroma→hljs post-pass

    // 4. Sink 2: the Model (same doc; unchanged; engine-agnostic).
    m := model.Build(doc, source, pc)

    // 5. Sanitize LAST — over the complete HTML string only (never CSS/Model).
    policy := opts.Sanitize
    if policy == nil { policy = sanitize.Policy() } // built-in always-on
    html = policy.Sanitize(html)

    // 6. Pack CSS from the EMBEDDED ThemeSet, theme resolved opts→front-matter→"default".
    css, err := packThemeCSS(opts, pc, m.Meta) // press/themes.ThemeSet + selection
    if err != nil { return Output{}, err }

    return Output{HTML: html, CSS: css, Model: m, Meta: m.Meta, Comments: flattenNotes(m)}, nil
}
```

Theme resolution (research Open Question #2, RESOLVED): `opts.Theme` → front-matter `theme:` (`m.Meta.Directives["theme"]`) → `"default"` (NOT bare scaffold — press deviates from chase.go's scaffold-only default to match Marp). Build the ThemeSet once via `press/themes.ThemeSet(profile.UnitElement(), profile.Scaffold(false), advBg, profile.Sizes().ByName)` (03-02), then `ts.Pack(selectedName, PackOptions{InlineSVG: opts.InlineSVG})`.

Comments aggregation (research "model.Section.Notes already exists"): pure flatten, no AST walk:
```go
// comments.go
func flattenNotes(d *model.Document) []string {
    var out []string
    for _, s := range d.Sections { out = append(out, s.Notes...) }
    return out
}
```

<anti_patterns>
- Do NOT modify `chase/chase.go` or call `chase.Render` — `press.Render` is a SIBLING composition (research "avoids touching chase.Render/chase.go at all"). Building on top of chase.Render would re-parse and break the one-parse invariant.
- Do NOT call `markdown.Parse` or `markdown.ParseWithEngine` more than ONCE per Render — the whole design is one parse, two sinks. A second parse is the exact anti-pattern the architecture forbids.
- Do NOT sanitize before the batteries render, per-node, or over the CSS/Model — sanitize is the LAST pass over the complete HTML string only (research "sanitize must be the LAST step").
- Do NOT build Output.Comments with a new `ast.Walk` — aggregate `Model.Sections[*].Notes` (already built by model.Build). A second walk duplicates chase/model's isNote logic (research pitfall).
- Do NOT import `chromedp` (transitively) anywhere under press/ — the CI gate enforces it; keep press pure-Go.
</anti_patterns>

- If the capstone corpus/cssdiff comparison fails for a theme: the failure is usually inline-SVG mode mismatch (set `opts.InlineSVG` to match the corpus case) or a battery altering expected output — diff the specific case; note genuine Marp-fidelity gaps as documented baseline (math/fit are Objective-8 territory) rather than forcing a match.

- One-parse invariant proof: assert with a counting wrapper or by structural argument in a test (e.g., a test that fails if `markdown.Parse`/`ParseWithEngine` were called twice) — research requires "press.Render must call ParseWithEngine exactly once."
