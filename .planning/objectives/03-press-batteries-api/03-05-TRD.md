<codebase_examples>
`github.com/yuin/goldmark-highlighting/v2` (cached; pinned in 03-01) wires chroma as a fenced-code NodeRenderer. Reuse it, injecting `chromahtml.WithClasses(true)` via its `WithFormatOptions`:

```go
package press

import (
    "github.com/yuin/goldmark"
    highlighting "github.com/yuin/goldmark-highlighting/v2"
    chromahtml "github.com/alecthomas/chroma/v2/formatters/html"
)

// highlightOption returns the goldmark.Option press.Render folds into
// NewEngine(pressExtraOpts...). WithClasses(true) makes chroma emit classes
// (not inline styles); the class names are chroma's short codes, remapped to
// .hljs-* by remapHLJS (below) as a post-render string pass.
func highlightOption(style string) goldmark.Option {
    return goldmark.WithExtensions(
        highlighting.NewHighlighting(
            highlighting.WithStyle(style),                 // "" → default; from Options.HighlightStyle
            highlighting.WithFormatOptions(chromahtml.WithClasses(true)),
        ),
    )
}
```

The remap is research option (a) — a bounded post-format string/regex replace over chroma's `<span class="kd">`→`<span class="hljs-keyword">` markup. The table's KEYS are chroma's `chroma.StandardTypes` short codes; the TARGET `.hljs-*` names are the set the bundled themes reference. Derive that target set from the compiled CSS acquired in 03-02:

```sh
# ground-truth: what .hljs-* selectors do the bundled themes actually style?
grep -oh '\.hljs-[a-z-]\+' themes/*.css | sort -u
```
Map each chroma short code that corresponds to a highlighted token (keyword, string, comment, number, name, function, …) to its `.hljs-*` counterpart present in that set. Leave chroma classes with no `.hljs-*` counterpart untouched (don't drop them). goldmark-highlighting's `WithCSSWriter` can also emit chroma's own stylesheet if a style needs to ship — but the bundled themes already carry the `.hljs-*` rules, so the remap makes chroma's output match them (research option a keeps the theme CSS verbatim).

STACK.md §3 confirms `chroma/v2` first-class support for `WithClasses(true)`, `StandardTypes` short names, `HighlightLines`, and `WriteCSS`.

<anti_patterns>
- Do NOT hand-roll a fenced-code NodeRenderer — goldmark-highlighting/v2 already does language lookup (`lexers.Get`/`Analyse`), `chroma.Coalesce`, per-block attribute overrides, and the CSSWriter hook (research Don't Hand-Roll row 3).
- Do NOT build the chroma→hljs table from memory/training data — chroma's taxonomy has NO relationship to highlight.js's, and the exact `.hljs-*` set is theme-specific. DERIVE it from the acquired compiled CSS (research Open Question #3: "grep -o '\\.hljs-[a-z-]+', not from memory").
- Do NOT regenerate/alter the theme CSS to match chroma's classes (research option b) — that would break the "verbatim theme" requirement (CORE-01). Remap chroma's OUTPUT instead (option a).
- Do NOT drop chroma classes that have no `.hljs-*` mapping — leave them intact so styling degrades gracefully rather than losing tokens.
</anti_patterns>

- If goldmark-highlighting emits inline styles instead of classes: `WithClasses(true)` wasn't passed through `WithFormatOptions` (it's the format-options injection point, not a top-level option).
