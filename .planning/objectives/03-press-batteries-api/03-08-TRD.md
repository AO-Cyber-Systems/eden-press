<codebase_examples>
bluemonday (provisioned in 03-01) builds a blank-slate allow-list policy. STACK.md §11 confirms the API is sufficient to mirror Marp's `xss` rule-by-rule:

```go
package sanitize

import "github.com/microcosm-cc/bluemonday"

// Policy returns the built-in, always-on Marp-parity policy press.Render
// applies as the LAST post-render pass over the complete Output.HTML string.
func Policy() *bluemonday.Policy {
    p := bluemonday.NewPolicy()
    // ...allow the Marp v4-era element/attribute set (headings, lists, tables,
    //    code/pre, spans w/ class for chroma .hljs-*, a[href], img[src] for
    //    twemoji + math fallback, blockquote, br/hr, sub/sup/s/del/em/strong)...
    p.AllowElements("section", "svg", "foreignObject")            // inline-SVG container chain
    p.AllowElements("math", "mrow", "mi", "mn", "mo", "msup" /*…*/) // MathML (03-06)
    p.AllowAttrs("class").Globally()                              // chroma .hljs-*, fit marker class
    p.AllowAttrs("src", "alt").OnElements("img")                 // twemoji + math fallback <img>
    p.AllowURLSchemes("http", "https", "data")                   // data: for base64 PNG math fallback
    p.RequireParseableURLs(true)                                 // block javascript: (research backstop)
    // Deliberately DO NOT AllowAttrs("style") — bluemonday has no CSS-value sanitizer.
    return p
}
```

The GFM disallowed-raw-HTML tagfilter (research Pitfall 12 / PITFALLS security table): goldmark's GFM extension does NOT filter these, so the policy/tagfilter must remove `<script>`, `<iframe>`, `<style>`, `<textarea>`, `<title>`, `<xmp>`, `<noembed>`, `<noframes>`, `<plaintext>`. A blank-slate bluemonday policy already drops unlisted elements (they're not allowed), which covers most; verify explicitly with adversarial tests and add any escaping nuance in `tagfilter.go` if strip-vs-escape parity matters for a specific tag.

Battery output the allow-list MUST preserve (co-design — from the sibling TRDs' documented shapes):
- twemoji `<img class=... src=...>` (03-04) · chroma `<span class="hljs-*">` (03-05) · `<s>` (03-03) · `<math>…</math>` + fallback `<img src="data:image/png;base64,…">` (03-06) · `<svg><foreignObject><section>` inline-SVG chain · CORE-09 fit attribute/class (03-07).

Research "directive/comment trust boundary is narrower than it sounds": directive-derived attribute values already go through `util.EscapeHTML` in chase/markdown/render.go; the real residual risks are `javascript:` URI schemes (bluemonday's URL-scheme policy is the backstop) and the GFM disallowed tags (tagfilter) — both are SANITIZE-layer concerns targeting the FINAL HTML, not a directive-parser change.

<anti_patterns>
- Do NOT run sanitize per-AST-node or before the batteries render — it must be ONE pass over the fully-rendered HTML string, after every NodeRenderer and `.marpit` wrapping (research "sanitize must be the LAST step"). This TRD authors the policy; 03-09 applies it last.
- Do NOT allow the `style` attribute — bluemonday has no CSS-value sanitizer; excluding `style` entirely is a deliberate, documented deviation from any upstream policy that permits some CSS (research security table).
- Do NOT write the security tests as a static allow-list comparison — write ADVERSARIAL round-trip tests over the final HTML string (research Pitfall 12: "static tag-list comparison hides strip-vs-escape and always-parsed-comment gaps").
- Do NOT sanitize the CSS or the Model — ONLY `Output.HTML`. Sanitizing CSS would mangle chroma's structural spans / theme CSS; the Model is data, not markup.
- Do NOT strip battery markup — the allow-list is co-designed to KEEP emoji `<img>`, MathML, inline-SVG chain, and fit markers (research explicit guard: "sanitize must NOT strip the inline-SVG container, MathML elements, `<!--fit-->` markers, or emoji `<img>`").
</anti_patterns>

<error_recovery>
- If sanitize strips a battery's output (surfaced when 03-09 integrates): the allow-list missed that element/attribute — add it to the policy and add a preservation test. This is why the allow-list is co-designed here from the sibling TRDs' documented output shapes (Task 2 exercises them).
- If a crafted `javascript:href` survives: `RequireParseableURLs(true)` + an explicit `AllowURLSchemes("http","https","data")` (or `AllowStandardURLs`) is missing — scheme allow-listing is the backstop, not attribute escaping.
- If the exact Marp v4 allow-list differs from an assumed one: the v4 relaxation is material (FEATURES.md: "pin to the CURRENT v4-era allow-list, not an older/stricter one"). Where the precise set is uncertain, err toward the batteries + common layout tags Marp v4 permits, and DOCUMENT the strip-vs-escape deviation; exhaustive byte-parity with the JS xss lib is an Objective-hardening concern, behavioral neutralization of XSS is the CORE-05 bar.
- `<!--fit-->`: if CORE-09 (03-07) emits the fit marker as a bare comment, bluemonday may strip comments — coordinate so the marker is an attribute/class on a real element (03-07 anti_pattern), which the allow-list keeps.
</error_recovery>
