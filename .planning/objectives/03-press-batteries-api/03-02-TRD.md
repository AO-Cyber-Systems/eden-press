<objective>
Bundle the three official Marp themes (default/gaia/uncover) VERBATIM via `go:embed` with preserved MIT headers (CORE-01, LIC-03's per-file-header half). The load-bearing risk (research riskiest-item #1): the npm package ships NO precompiled per-theme `.css` — only Sass source that Go cannot process and that would not byte-match marp-core if hand-recompiled. So this TRD extends the existing `tools/corpus-gen` npm oracle to dump each theme's fully-compiled CSS through marp-core's own API, guaranteeing byte-parity, then embeds those verbatim and builds a `chase/theme.ThemeSet` keyed by name.

Purpose: "Exercise all 3 themes" is an Objective-3 success criterion and the CSS backbone every battery styles against; the acquisition mechanism is the #1 risk and gets its own spike task. The compiled `default.css` is also the ground truth 03-05's chroma→`.hljs-*` remap is derived from.
Output: `themes/*.css` + `themes/browser-fit.js` (verbatim, attributed) + `press/themes` ThemeSet builder + NOTICE/CI updates.
</objective>

<anti_patterns>
- Do NOT `go:embed` the raw `themes/*.scss` (Sass source using `@use 'sass:meta'; @include meta.load-css('pkg:github-markdown-css/...')` — Go can't process it, and hand-recompiling risks output that doesn't byte-match marp-core, defeating "verbatim"). Extract the COMPILED CSS through marp-core's own API (research "SCSS is not the artifact to embed").
- Do NOT prepend an AO-Cyber `addlicense` header to the `.css` files. Two reasons: (1) these are verbatim Marp assets carrying Marp's own `/*! */` header, not Eden originals; (2) an added leading comment would displace the `/*! @theme */` block, so `chase/theme/meta.go`'s `leadingComment()` (grabs the FIRST comment only) would capture the wrong block and `ParseMeta` fails with "missing required @theme metadata" (research "SCSS is not embeddable CSS as-is" pitfall). Instead, `-ignore` them in the AO-Cyber CI check and let their `/*! */` block be the header.
- Do NOT relabel the theme copyright to 2026/AO Cyber. Preserve Marp's `Copyright (c) 2018 Marp team (marp-team@marp.app)` (CONTRIBUTING.md template #2; NOTICE already reserves this).
- Do NOT make `press/themes` import `press` (import cycle — press imports press/themes, not vice-versa).
</anti_patterns>

```go
// ThemeSet builds a *theme.ThemeSet with the three embedded Marp themes
// registered under their @theme names, plus the caller-supplied scaffold /
// advanced-background / unit (from the active profile — see chase/chase.go
// packCSS). Every consumer (press.Render) resolves opts.Theme against this set.
func ThemeSet(unit, scaffoldCSS, advancedBackgroundCSS string, sizeFallback map[string]theme.Size) (*theme.ThemeSet, error) {
    ts := theme.NewThemeSet(unit, scaffoldCSS, advancedBackgroundCSS)
    for _, css := range []string{DefaultCSS, GaiaCSS, UncoverCSS} {
        th, err := theme.Load(css, unit, sizeFallback) // errors if @theme missing
        if err != nil { return nil, err }
        ts.Add(th)
    }
    return ts, nil
}
// BrowserFitJS returns the verbatim Marp fit helper for a viewer-side consumer (CORE-09).
func BrowserFitJS() string { return BrowserFitJSAsset }
```
