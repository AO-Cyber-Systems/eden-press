<codebase_examples>
**Current OTF embed + @font-face (convert/chrome/fonts.go) — the pattern to extend:**
```go
//go:embed fonts/STIXTwoMath-Regular.otf
var stixTwoMathOTF []byte
const fontFaceCSS = `@font-face{font-family:'STIX Two Math';src:url(data:font/otf;base64,%s) format('opentype');}`
func FontFaceDataURI() string {
    if len(stixTwoMathOTF) == 0 { return "" }
    b64 := base64.StdEncoding.EncodeToString(stixTwoMathOTF)
    return fmt.Sprintf(fontFaceCSS, b64)
}
```
Add a sibling `//go:embed fonts/STIXTwoMath-Regular.woff2` + a woff2 @font-face variant (`src:url(data:font/woff2;base64,%s) format('woff2')`). Prefer the WOFF2 in the src list (browsers pick the first supported), keeping OTF as fallback — so one `@font-face` can offer both, or expose a `FontFaceDataURIWoff2()` the serve/preview path uses.

**Reuse the determinism recipe (convert/chrome/determinism.go) — its own doc comment states the exact contract:** *"'deterministic' here means pixel-diff-under-threshold, NOT byte-identical … Chrome's own rendering pipeline has acknowledged PRNG-based non-determinism."* The MATH-table smoke is the SAME kind of check — render deterministically, compare under a threshold. Do NOT re-derive a tolerance model.

**Chrome-presence-gated test pattern (see convert/chrome/*_test.go + scripts/check-chrome-export.sh):** the existing Chrome tests t.Skip when no Chrome binary is discoverable (convert/chrome/discover.go). Mirror that — the smoke runs everywhere structurally but only pixel-checks when Chrome is present.

**MATH-table survival check (no Chrome needed):** the OpenType MATH table is a named SFNT table (`MATH`). Verify the WOFF2 decompresses to a font that still contains it — e.g. shell out to `fonttools ttx -t MATH -o - <woff2>` and assert non-empty, or decode the WOFF2 table directory in Go and assert a `MATH` tag entry is present. This is the survival proof the conversion didn't subset it away.

<anti_patterns>
- Do NOT re-source STIX from a CDN or Google Fonts — those subset away the MATH table (the exact bug the verbatim bundling avoids; NOTICE + fonts.go doc comment cite it). Convert from the LOCAL verbatim OTF, or use stipub's own official WOFF2 build.
- Do NOT subset during conversion — WOFF2 here is a lossless recompression of the SAME glyph+table set (including MATH). A subsetting tool invocation would silently reintroduce tofu (research Pitfall / error_recovery).
- Do NOT add an image-diff library or SSIM implementation — Go stdlib image/png + a threshold/region check is a few dozen lines and reuses the determinism contract (research Don't Hand-Roll).
- Do NOT make the smoke HARD-require Chrome — it must t.Skip cleanly where Chrome is absent (so `go test ./...` stays green in CI without a browser), matching the existing convert/chrome test posture.
- Do NOT AO-stamp the .woff2 binary — convert/chrome/fonts/** is already addlicense-ignored (verbatim third-party asset); the NOTICE entry is its attribution.
</anti_patterns>

<error_recovery>
- If no official stipub WOFF2 exists at the v2.13 tag: convert the local OTF with `woff2_compress` (the reference tool) or `fonttools`'s WOFF2 support, NON-subsetting, then run the MATH-table survival check. If the MATH table is ABSENT post-conversion, the tool subsetted — re-run with subsetting disabled (fonttools: do not pass a subset; woff2_compress does not subset by default).
- If the pixel-check is flaky across environments: widen the threshold per the determinism contract (pixel-diff-under-threshold), or narrow the compared region to the operator glyph's bounding box; do NOT switch to byte-identical comparison (Chrome output isn't byte-deterministic).
- If FontFaceDataURI's WOFF2 variant breaks an existing convert/chrome or export test that asserts the OTF `format('opentype')` string: keep the OTF variant available (add WOFF2 as an ADDITIONAL src/accessor, don't replace) so existing assertions stay valid; expose WOFF2 via a new accessor if replacing in-place is disruptive.
</error_recovery>
