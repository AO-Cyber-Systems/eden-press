**binom/pmatrix shared-fence asymmetry — converter.go convertAndAppendCommand (~lines 522-565):**
```go
func convertAndAppendCommand(command string, parent *etree.Element, attributes map[string]string) { … }
// pmatrix branch (~541): fence built with an EMPTY attribute map — no sizing hint
convertAndAppendCommand(`\lparen`, parent, map[string]string{})
// binom branch (~543): fence built WITH content-height sizing
convertAndAppendCommand(`\lparen`, parent, map[string]string{"minsize": size, "maxsize": size})
```
The asymmetry (one branch has minsize/maxsize, one is empty) is the likely "shared-fence" mechanism. PROPOSAL §11 also reports the opening `(` emitted AS the closing fence (`<mo>(</mo>…<mo>(</mo>`) — verify whether the closing-delimiter selection (the postfix element) reuses the opening delimiter char. Fix candidates: (a) pass minsize/maxsize to the pmatrix branch too; (b) correct the postfix fence to emit the matching CLOSING delimiter `)`.

**aligned→mtable — the working ALIGN path to mirror (research HIGH confidence):** `\begin{align*}` (the ALIGN token) IS in the `MATRICES` list, dispatched at converter.go:438 (`slices.Contains(MATRICES, command)`) → `convertMatrix` → `<mtable>` with `columnalign="right left"`. `\begin{aligned}` produces the token `\aligned`, which is ABSENT from MATRICES, so it falls through to generic handling (literal `<mi>&</mi>`). Fix IN-FORK: register `\aligned` as a MATRICES environment handled identically to ALIGN (columnalign "right left"). (Research notes the equivalent textual pre-process — rewrite `\begin{aligned}`→`\begin{align*}` before Convert — is the documented fallback if the in-fork MATRICES registration proves larger than a one-line addition.)

**mathvariant emission — converter.go (research traced ~line 745, `element.CreateAttr("mathvariant", value)`):** the converter emits e.g. `<mi mathvariant="double-struck">R</mi>`; MathML Core ignores non-`normal` mathvariant. Fix IN-FORK: build a variant→codepoint lookup (letter + variant → Unicode Mathematical Alphanumeric Symbols codepoint) and set the element TEXT to the codepoint instead of the attribute. Confirmed targets (PROPOSAL §11 variant.png): `\mathbb{R}`→ℝ U+211D, `\mathbf{v}`→𝐯 U+1D42F, `\mathcal{L}`→ℒ U+2112. Drop the now-redundant mathvariant attribute.
