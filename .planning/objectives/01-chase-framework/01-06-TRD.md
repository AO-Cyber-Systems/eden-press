<objective>
Wire directive resolution into `chase/markdown`: an ASTTransformer that walks the Section/Comment nodes from 01-05, drives 01-02's carry-forward state machine, and materializes the resolved directives onto each `<section>` as `data-*` attributes + an ordered inline style, including the 4 special CSS overrides and the two-pass pagination counter (PARSE-04).

Purpose: This is where directive VALUES become observable HTML the corpus checks byte-for-byte. Declaration order in the inline `style` attribute is cascade-significant and directly compared by htmldiff — a Go map would flake it (RESEARCH §"Don't Hand-Roll"). The pagination total requires a second pass after full slide-list construction.

Output: `chase/markdown/{directive.go, inline_style.go, apply.go}` + modifications to markdown.go (register transformer) and render.go (emit attrs/style) + tests turning marp-class-spot / marp-paginate / marp-header-footer structurally green (sans Objective-3 batteries).
</objective>

<anti_patterns>
- DO NOT use `map[string]string` for the inline style (RESEARCH §"Don't Hand-Roll"). Declaration order is cascade-significant and htmldiff-compared. Use an ordered builder with `.Set(prop, value)` (first-seen order stable, last-write-wins per property).
- DO NOT recompute the pagination total inline. Collect paginating slides during the main loop, then patch `data-marpit-pagination-total` in a trailing pass (RESEARCH §"Directive → Attribute/Style materialization" item 4).
- DO NOT re-implement carry-forward here — call `chase/directive`. This transformer only builds the ordered event stream and applies the resolved output.
</anti_patterns>
