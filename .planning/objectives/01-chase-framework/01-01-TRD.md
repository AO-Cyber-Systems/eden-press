<objective>
Build `chase/theme/selector` — the standalone CSS selector-rewriter subsystem (THEME-04). It has no upstream Go analogue and is the single riskiest, most reusable primitive in `chase/theme`, so it is built and unit-tested IN ISOLATION first, before any theme-pipeline code imports it.

Purpose: The theme-CSS scoping pipeline (TRD 01-04) needs to prepend a container/slide combinator chain onto every rule selector and defer a `:root` specificity trick until after scoping. Doing this as string concatenation breaks on multi-selector rules and `:is()/:where()` function arguments (RESEARCH Pitfall 3). This subsystem does it at the tdewolff token level.

Output: `chase/theme/selector/` package with a token-level Selector model, two-step placeholder scoping, `:root` sentinel rewrite, and a dedicated test suite — satisfying ROADMAP success criterion 5 ("selector-rewriter exists as its own independently unit-tested subsystem").
</objective>

<anti_patterns>
- DO NOT prepend a raw string prefix (`"div.marpit > svg > foreignObject > section "`) to selector text. It works for `section` but corrupts `h1, h2` (each compound needs its own prefix) and `:is(h1, marp-h1)` (function args must not be prefixed). RESEARCH Pitfall 3.
- DO NOT descend into `FunctionToken` arguments during the scope-PREPEND step. DO walk into `:is()/:where()` args during the `:root`-marker REWRITE step (markers can appear nested — confirmed in `marp-theme-gaia/expected.css`).
- DO NOT split the top-level selector list on commas that live inside strings, `[attr="a,b"]`, or `:is(a, b)` — split only on TOP-LEVEL (unnested, unquoted) commas.
</anti_patterns>

<error_recovery>
- If a gaia-shaped selector fails, treat `marp-theme-gaia/expected.css` (already in the corpus) as the canonical regression fixture — grep it for `:where(:is(` and `:not([` to see real target output.
- The `[\20 root]` is a CSS-escaped attribute selector for an attribute literally named "<SPACE>root" — impossible to author, so it never matches; `:where()` contributes 0 specificity while `:not([\20 root])` contributes one attribute-selector (0-1-0), outranking a plain `section` (0-0-1). Emit these as literal token text; do not "normalize" the escape away.
</error_recovery>

From 01-RESEARCH.md §"The Selector-Rewriter Subsystem" + §"The `:root` specificity trick":
- Final scoped chain (verified against corpus): `div.marpit > svg > foreignObject > section` (inline-SVG) / `div.marpit > section` (non-SVG). It is a `>`-combinator CHAIN, not a descendant prefix.
- Two-step scoping: (1) prepend `:marpit-container > :marpit-slide ` placeholder to every selector; (2) substitute placeholders with the real element chain. Copy this sentinel design directly.
- `:root` handling is 4 ordered steps: (1) add-time `:root` → `:marpit-root` sentinel; (2) render-time second `:root` pass; (3) scope-prefix chain prepended to all selectors incl. those carrying the marker; (4) LAST, after scoping, `:marpit-root` → `:where(section):not([\20 root])`. This subsystem owns steps (1), (3-mechanics), and (4). The pipeline (01-04) sequences them.
</research_context>

## Test list
(test_list_first required — write these as failing tests before implementation; happy → edge → failure)

1. `section` → `div.marpit > svg > foreignObject > section` (inline-SVG mode).
2. `section` → `div.marpit > section` (non-SVG mode).
3. `h1, h2` → each compound prefixed: `div.marpit > … > section h1, div.marpit > … > section h2`.
4. `:is(h3, h4) + p` → prefix applied to the outer compound; `:is(...)` args untouched; `+ p` combinator preserved.
5. `:root { … }` at add-time → `:marpit-root` sentinel present.
6. After scope-prefix, `:marpit-root` → `:where(section):not([\20 root])` (specificity trick, runs LAST).
7. `:where(:is(h1, marp-h1))` carrying a `:root` marker nested inside — marker is found and rewritten (gaia regression).
8. Edge: top-level comma split ignores commas inside `[data-x="a,b"]`, strings, and `:is(a, b)`.
9. Edge: an already-scoped or empty selector is a no-op (idempotent / safe).
