<objective>
Build the `chase/theme` foundation: the owned `Stylesheet{Meta, Rules, Atoms}` model (THEME-01) and the theme metadata parse (THEME-02). This is the parallel sibling of `chase/directive` and the input to the scoping pipeline (TRD 01-04). ZERO markdown/goldmark dependency — CSS themes are parsed completely independently of slide content.

Purpose: The scoping pipeline needs a model that preserves selector TOKEN LISTS (so the selector-rewriter can walk `:is()/:where()` args) and nesting depth (so the nesting down-leveler has structure to flatten) — richer than the string-based `conformance/cssdiff` model. Metadata (`@theme`/`@size`/`@auto-scaling`) drives theme identity and the SVG viewBox dimensions.

Output: `chase/theme/{stylesheet.go, parse.go, meta.go}` + tests — a token-preserving Stylesheet builder and metadata extractor.
</objective>

## Test list
(test_list_first required — write failing tests first; happy → edge → failure)

1. Parse `section { color: red }` → one Rule, SelectorTokens preserved, one Declaration.
2. Parse `h1, h2 { margin: 0 }` → selector token list retains the comma (walkable), not pre-split.
3. Nested rule `section { & h1 { color: red } }` → inner rule captured with NestingDepth=1 (NOT flattened).
4. `@import "x.css";` and `@import-theme "y";` captured as at-rule records (NOT resolved).
5. `@theme stress` present → Meta.Name == "stress".
6. Missing `@theme` → Parse/meta returns an error.
7. `@size 16:9 1280px 720px` + `@size 4:3 960px 720px` → size table with both entries; default resolves to 1280×720.
8. `@auto-scaling true` → Meta.AutoScaling captured.
