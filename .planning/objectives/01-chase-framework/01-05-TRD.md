<objective>
Build the `chase/markdown` core plumbing: the goldmark Extender, the HTML-comment BlockParser/InlineParser (wrapping 01-02's detector into AST nodes), the slide-splitting ASTTransformer, the heading-divider ASTTransformer, the custom Section node, and the base NodeRenderer that emits the `.marpit` container + `<section>` wrappers (PARSE-05). This is the AST skeleton that TRDs 01-06 (directives) and 01-07 (backgrounds/inline-SVG) build on.

Purpose: Marpit's real value starts with turning a flat CommonMark AST into slide `<section>`s. goldmark's fixed block-parser priority already resolves the setext-H2-vs-thematic-break ambiguity for free (RESEARCH §"Slide-Splitting"), so the transformer can treat every remaining `*ast.ThematicBreak` as a genuine separator. The container is injected at render time (mirrors Marpit's marpitContainer / renderMarkdown split) — the AST seam Objective 2 will reuse.

Output: `chase/markdown/{markdown.go, comment.go, slide.go, headingdivider.go, section.go, render.go}` + structural tests.
</objective>

```go
func (e *ext) Extend(m goldmark.Markdown) {
    m.Parser().AddOptions(parser.WithBlockParsers(
        util.Prioritized(newCommentBlockParser(), 0),
    ), parser.WithInlineParsers(
        util.Prioritized(newCommentInlineParser(), 0),
    ))
    m.Parser().AddOptions(parser.WithASTTransformers(
        util.Prioritized(newHeadingDividerTransformer(), 100), // BEFORE slide-split
        util.Prioritized(newSlideSplitTransformer(), 200),     // consumes all breaks uniformly
    ))
}
```

<anti_patterns>
- DO NOT write special-case detection for the setext-H2 trap. By the time an ASTTransformer runs, goldmark has already consumed genuine setext underlines into `*ast.Heading` — every remaining sibling `*ast.ThematicBreak` is a real slide separator (RESEARCH §"Slide-Splitting … setext-H2 trap RESOLVED"). Adding detection re-introduces a bug goldmark prevents.
- DO NOT inject the `.marpit` container as an AST node at parse time. Inject it at render time (Marpit's marpitContainer/renderMarkdown split) so the AST holds only sections — the seam Objective 2 hooks.
- DO NOT decide directive recognition in comment.go (RESEARCH Pitfall 4). Detect + store raw kv on the node ONLY; recognition is TRD 01-06.
- DO NOT run `md.Convert()` in production paths — the two-phase seam is TRD 01-08's canonical entrypoint. In THIS TRD's tests you may call `md.Parser().Parse()` + `md.Renderer().Render()` directly.
</anti_patterns>

<error_recovery>
- Register the comment BlockParser at a priority that wins the race against goldmark's built-in raw-HTML block parser (numerically lower / "before"), so `<!-- -->` is captured as a CommentNode, not an HTMLBlock. Verify by asserting the AST node kind.
- If slide `id`s are off-by-one, remember the corpus uses `id="{index+1}"` (first slide → "1"). See `marp-slide-split/expected.html`.
- Heading-divider ordering: insert synthetic `*ast.ThematicBreak` BEFORE qualifying headings, THEN let the generic splitter consume all breaks — do NOT run two independent split algorithms (RESEARCH §"Slide-Splitting").
</error_recovery>

(test_list_first required — write failing tests first; happy → edge → failure)

1. `# A\n\n---\n\n# B` → two `<section id="1">`/`<section id="2">` inside one `<div class="marpit">`; the `---` is dropped.
2. Single slide (no `---`) → one `<section id="1">` in the container.
3. setext-H2 trap: `Intro\n---\n\nbody` → one slide; the `---` is an H2 underline (an `*ast.Heading`), NOT a break.
4. headingDivider=1: `# A\n\n# B` (with directive value injected) → synthetic breaks inserted → two slides.
5. `<!-- foo: bar -->` → a hidden CommentNode carrying raw kv `{foo: bar}`; not rendered as visible text; not yet recognized as a directive.
6. Inline comment mid-paragraph (`text <!-- x --> more`) → detected as an inline CommentNode.
7. Two-phase seam sanity: `md.Parser().Parse()` returns an `*ast.Document` whose children include Section nodes BEFORE `Render()` is called.
