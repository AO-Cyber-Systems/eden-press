<objective>
Seed the golden corpus (CONF-01) from Marp's own MIT-licensed test suite — NOT by hand-
transcribing Jest `expect()` assertions, but by rendering hand-curated (markdown, options)
inputs through the REAL @marp-team npm packages via a small throwaway Node harness (the proven
ref.mjs pattern), capturing ground-truth output into the corpus case format. Then wire the
corpus runner that later objectives' engines must satisfy.

Purpose: CONF-01's "Jest snapshot fixtures" is a misnomer — Marp has ~no literal .snap golden
files (00-RESEARCH.md Pitfall 1). The reusable substance is Marp's real render output, mined
by installing the actual package and rendering real inputs. This gives the corpus ground truth
that is exactly what upstream Marp produces.

Output: tools/corpus-gen (npm oracle harness), conformance/corpus/cases/* (generated golden
cases), conformance/runner/corpus_test.go (per-case pass/fail/pending runner), NOTICE updated.
</objective>

## Test list

- Every case's options.json declares a requires_engine value in {commonmark, marpit, marp-core}.

  Equal (green) — proving the runner + htmldiff wiring works end-to-end on real data.

  pass and NOT as hard failures — the corpus exists as the gate before the engine.
- The report enumerates counts of {pass, fail, pending} and Render() lists them per section/id.
- A deliberately malformed case dir surfaces a clear load error (reuse corpus.LoadCases behavior).
