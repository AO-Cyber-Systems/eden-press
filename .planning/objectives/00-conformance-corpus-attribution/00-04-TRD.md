<objective>
Vendor the full CommonMark + GFM spec suites and stand up the spec-sweep runner: bind each
spec example to a render, DOM-diff via htmldiff, and track pass/fail PER SPEC SECTION. This is
the CONF-04 acceptance gate — the full sweep (not the 32-case parser spike) that every engine
objective is validated against, with per-section reporting so a high aggregate can never hide
a 0%-passing gnarly section (tabs, loose lists, raw-HTML blocks).

Purpose: The 32-case spike downgraded base-parser risk but did not retire it (PITFALLS.md
Pitfall 1). The full sweep, tracked per section, is the ongoing gate.

Output: conformance/spec/{commonmark,gfm}/*.json (vendored, generated via the official
spec_tests.py dump), conformance/runner/spec_test.go (per-section sweep), NOTICE updated.
</objective>

type specExample struct {
    Markdown  string `json:"markdown"`
    HTML      string `json:"html"`
    Example   int    `json:"example"`
    StartLine int    `json:"start_line"`
    EndLine   int    `json:"end_line"`
    Section   string `json:"section"`
}

<anti_patterns>
<!-- 00-RESEARCH.md Anti-Patterns + PITFALLS.md Pitfall 1 -->
- DO NOT use the frozen 0.29.0.gfm.13 (2019) GFM snapshot or the public gfm.github.io page as
  the source. Use the LIVE cmark-gfm master split (test/spec.txt + test/extensions.txt), which
  is actively synced with upstream CommonMark and naturally section-tagged.
- DO NOT fetch/parse spec.txt at test time. Vendor the generated spec.json and go:embed it
  (goldmark itself commits a static _test/spec.json rather than regenerating per run).
- DO NOT report only an aggregate percentage. A 97% aggregate can hide a 0%-passing section
  (tabs, loose-list determination). Track pass/fail PER SECTION.
- DO NOT hand-copy examples out of the rendered spec pages — use the official dump script.
- The "~672 GFM examples" figure in older docs is a 2019 artifact; record the ACTUAL measured
  counts from the vendored files in VERSIONS.txt + NOTICE (research measured 650 + 30 = 680).
</anti_patterns>

## Test list

Per test_first=required — behavior cases for the spec sweep:

- Each vendored suite (commonmark/spec.json, gfm/spec.json, gfm/extensions.json) unmarshals
  into a non-empty []specExample.
- The measured example counts match VERSIONS.txt (guards against a truncated/corrupt vendor).
- The sweep renders every example through the correct goldmark engine (base vs GFM) and
  DOM-diffs via htmldiff.Equal, recording each result under its section.
- The emitted per-section report contains EVERY section present in the suites (no section
  silently dropped).
- Known-divergence examples (strikethrough <s>/<del>) are attributed to the allow-list and do
  not fail the gate; a NON-allow-listed regression WOULD fail (assert the allow-list is
  consulted, e.g., by injecting a synthetic allow-listed section and confirming it is excluded
  from the failing-section count).
- Summary() records aggregate pass/total and the failing-section count (the baseline).
