## Accomplishments
- `scripts/build-android.sh`: cross-compiles `bind/capi` to `libpress.so` (+ header) for all four Android ABIs (arm64-v8a, armeabi-v7a, x86_64, x86) via the NDK's own per-triple `<triple>21-clang` binaries as `CC`, with `CGO_ENABLED=1 GOOS=android`; verifies each output's actual arch with `file`; fails fast with a precise remediation message (not a cryptic clang error) when `ANDROID_NDK_HOME` is unset — confirmed exit 1 with guidance on this host, where the NDK is genuinely absent.
- `scripts/build-ios.sh`: **actually run end-to-end on this Xcode-equipped macOS host** — built three real c-archive slices (`device-arm64`, `sim-arm64`, `sim-x86_64`) via generated per-arch clang wrappers (iphoneos/iphonesimulator SDKs, pinned `-m*-version-min=13.0`), `lipo -create`'d the two simulator slices into one universal `.a` (`lipo -info` confirms `x86_64 arm64`), and packaged device + simulator-universal into `EdenPress.xcframework` via `xcodebuild -create-xcframework` — verified structurally to contain both an `ios-arm64` (device) and `ios-arm64_x86_64-simulator` slice directory, each with a `libpress.h` declaring `PressRender`/`PressFree`.

Each job runs only its own build script, then `bash scripts/check-no-chromedp.sh`.
- `.gitignore` extended with `*.so`, `*.a`, `*.dylib`, `*.xcframework/` — no native build product is ever committed.
- No `gomobile bind` anywhere in any script or workflow; `golang/go#47296` is not cited as a plain-cgo risk (it is scoped to gomobile's own `env.go`, correctly out of scope per RESEARCH Pitfall 5) — the two-job CI isolation is retained purely as hygiene.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `go build`'s `CC` must be an absolute path**
- **Found during:** Task 2 (first real run of `build-ios.sh`)
- **Issue:** `CC="bind/capi/build/ios/device-clangwrap.sh"` (relative) was rejected by the Go toolchain: `CC environment variable is relative; must be absolute path`.
- **Fix:** Resolved `BUILD_ROOT` to an absolute path (`cd "$BUILD_ROOT" && pwd`) immediately after `mkdir -p`, before generating any wrapper script.
- **Files modified:** `scripts/build-ios.sh`
- **Verification:** Re-ran `bash scripts/build-ios.sh` — all three slices, `lipo`, and the xcframework built successfully.
- **Committed in:** `c307f5c` (part of Task 2 commit; fixed before the task's single atomic commit).

**2. [Rule 1 - Bug] Dropped `-fembed-bitcode` from iOS `CGO_CFLAGS`**
- **Found during:** Task 2 (writing the build recipe, before running it)
- **Issue:** The RESEARCH §2 code example includes `CGO_CFLAGS="-fembed-bitcode"`, but Apple fully removed bitcode support starting Xcode 14 (2022); this project's Xcode is 26.6. Passing the flag would either be a silent no-op or a hard error depending on toolchain version, and is factually obsolete either way.
- **Fix:** Omitted the flag entirely; documented the omission and rationale in `build-ios.sh`'s decision list.
- **Files modified:** `scripts/build-ios.sh`
- **Verification:** Real device+simulator c-archive builds succeeded without it on this host.
- **Committed in:** `c307f5c` (part of Task 2 commit).

**3. [Rule 3 - Blocking] `env` context unavailable in job `name:` field**
- **Found during:** Task 3 (actionlint validation)
- **Issue:** `jobs.android-build.name: Android (... NDK ${{ env.ANDROID_NDK_VERSION }})` failed actionlint: the `env` context is not available where job names are resolved.
- **Fix:** Changed the job name to a static string; the pinned NDK version remains enforced via the workflow-level `env:` block consumed by `setup-ndk`'s `with:` input (functionally identical, just not echoed into the job's display name).
- **Files modified:** `.github/workflows/dart-native.yml`
- **Verification:** `actionlint .github/workflows/dart-native.yml` exits 0.
- **Committed in:** `31326dc` (part of Task 3 commit).
