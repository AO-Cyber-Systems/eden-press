<objective>
Build the single Go C-ABI core (DART-01): a pure-Go, platform-agnostic JSON marshalling function (`bind/capi/core.RenderJSON`) plus the cgo front door (`bind/capi` with `//export PressRender`/`PressFree`). This is the load-bearing foundation of the whole objective — every other TRD's front door (wasm shim 07-02, native builds 07-03, conformance harness 07-04, Dart client 07-05) stands on the one JSON boundary defined here.

Purpose: `press.Render(md, opts) → press.Output` is frozen (Objective 3, merged). DART-01 wraps it behind a JSON-in / JSON-out C ABI so a Flutter client never mirrors Go structs. RESEARCH Architecture Patterns §1 establishes the critical structural split: the *marshalling logic* is shared (one `core.RenderJSON`), but the *front door* is target-specific (cgo `//export` here vs. `syscall/js` in 07-02) because **cgo and `GOOS=js GOARCH=wasm` are mutually exclusive**. Getting this split right in Wave 1 makes the rest of the objective mechanical.
Output: `bind/capi/core.RenderJSON` (pure Go) + `bind/capi` cgo shim (`PressRender`/`PressFree`) + host-arch c-shared build script + the extended no-chromedp gate.
</objective>

<codebase_examples>
The frozen types RenderJSON marshals over (press/options.go, DO NOT redefine — import them):

```go
// press.Options — the JSON request maps onto THIS. Note Sanitize is a
// *bluemonday.Policy: it is NOT JSON-serializable and is deliberately OMITTED
// from the wire request (nil => the built-in always-on policy applies).
type Options struct {
    Theme          string             // "" => front-matter theme: => "default"
    Profile        string             // "" => profile.Default() ("slides")
    InlineSVG      bool               // baseline true to match Marp Core
    MathMode       string             // "" => "mathml"; "off" disables math
    NoHighlight    bool               // zero value => highlighting ON
    HighlightStyle string             // "" => default chroma style
    Sanitize       *bluemonday.Policy // nil => built-in policy (NOT over the wire)
}

// press.Output — the response envelope carries THIS, JSON-marshalled. Model is
// *model.Document (has json tags, incl. schemaVersion "eden-press.model/v1").
type Output struct {
    HTML     string
    CSS      string
    Model    *model.Document
    Meta     model.Meta
    Comments []string
}
```

The recover()-into-graceful-degradation pattern is already established in press/math (STATE.md: "fallback wraps recover() and degrades" — go-latex/mtex PANICS on some constructs). RenderJSON MUST wrap `press.Render` in the same `defer func(){ recover() }` shape so a math panic becomes a JSON error envelope, never a host-process crash across the C ABI.

cgo C.CString/C.GoString/C.free semantics (RESEARCH §1, pkg.go.dev/cmd/cgo, quoted): `C.CString` allocates on the C heap via malloc; "it is the caller's responsibility to arrange for it to be freed, such as by calling C.free". A `//export` function's returned `*C.char` outlives the call and is invisible to Go's GC — hence PressFree.
</codebase_examples>

<anti_patterns>
- Do NOT put `import "C"` or `//export` in bind/capi/core — core is pure Go so 07-02's `GOOS=js GOARCH=wasm` build (cgo unavailable on that port) can import the SAME function (RESEARCH Pitfall 1). The cgo lives ONLY in bind/capi/capi.go.
- Do NOT hand back a Go-native string/[]byte pointer across the C ABI. `C` "may not keep a copy of a Go pointer after the call returns" — copy into malloc'd C memory via C.CString (RESEARCH §1 memory-ownership).
- Do NOT let Dart free a Go-allocated pointer with its own allocator, and do NOT let RenderJSON return nil/empty on error — always emit a well-formed JSON error envelope so the boundary is uniformly parseable on the Dart side.
- Do NOT redefine press.Options/press.Output or add a math/code enrichment to the Model — that schema-v2 work is owned by Objective 6 (06-01) and consumed downstream in 07-05. This TRD only serializes the Output shape as it exists.
- Do NOT run `go mod tidy` (CONTRIBUTING.md additive-only). No new third-party deps are needed here — core imports only press + stdlib encoding/json.
</anti_patterns>

1. `RenderJSON` on a request `{"envelopeVersion":"eden-press.capi/v1","markdown":"# Hi"}` returns valid JSON whose parsed response has `envelopeVersion` set, `error` empty, and `output.html` containing a rendered `<h1` — the happy-path whole-envelope round-trip.
2. Full-shape losslessness: the parsed response `output` carries non-empty `html`, `css`, a non-nil `model` with `schemaVersion == "eden-press.model/v1"`, `meta`, and `comments` — proving the entire press.Output shape crosses JSON intact (the shape 07-05's Dart client consumes).
3. Option mapping: `{"options":{"noHighlight":true}}` yields HTML with no chroma class spans; `{"options":{"mathMode":"off"}}` leaves `$x$` literal; `{"options":{"theme":"gaia"}}` yields CSS distinct from the default theme — options map correctly onto press.Options.

5. Malformed request (`[]byte("not json")`) and an unknown `envelopeVersion` each return a well-formed JSON error envelope (`error` non-empty, `output` null), NEVER a nil/empty slice.
6. Panic recovery: a request whose math construct is known to panic go-latex under the default MathMode returns a JSON error envelope (recovered), and the surrounding `go test` process does not crash — proving no panic escapes toward the C/Dart host.
