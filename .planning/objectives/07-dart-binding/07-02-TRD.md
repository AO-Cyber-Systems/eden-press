<objective>
Build the web front door (DART-03): a `syscall/js` shim (`bind/wasm`) that registers a JS-global `pressRender` calling the shared `core.RenderJSON` (07-01), compiled with **standard Go** `GOOS=js GOARCH=wasm` (the resolved decision — no TinyGo path), plus a version-pinned `wasm_exec.js` loader and a Node smoke that round-trips through the compiled artifact.

Purpose: cgo and `GOOS=js GOARCH=wasm` are mutually exclusive (RESEARCH Pitfall 1) — the web target CANNOT reuse 07-01's cgo shim; it needs a separate `syscall/js`-based `package main` that calls the SAME pure-Go core. This TRD delivers that separate front door and the loader/version-pin discipline (RESEARCH Pitfall 2) so the `.wasm` and its `wasm_exec.js` never drift.
Output: `bind/wasm/main.go` (syscall/js shim) + `scripts/build-wasm.sh` + `scripts/check-wasm-exec-version.sh` + `bind/wasm/smoke/smoke.mjs`.
</objective>

<codebase_examples>
The shared seam this shim calls (defined in 07-01, DO NOT re-implement):
```go
// bind/capi/core (pure Go, no cgo, no build tags) — importable under GOOS=js:
func RenderJSON(cmd []byte) []byte  // always-well-formed JSON envelope in/out
```

goldmark is already confirmed `js`-target-safe from its vendored source (RESEARCH §3): `github.com/yuin/goldmark/util/util_safe.go` gates its `unsafe.String` fast path `!appengine && !js` with an `appengine || js` copying fallback — so the whole press dependency chain (goldmark + chroma + latex2mathml + bluemonday) compiles under `GOOS=js` with standard Go. A real precedent (goldmark + standard-Go WASM, `milinddethe15/render-md`) exists; TinyGo + the full press chain has NO such precedent — hence standard Go.

syscall/js registration shape (illustrative — the pattern, not prescribed code):
```go
//go:build js && wasm
package main
import "syscall/js"
func main() {
    js.Global().Set("pressRender", js.FuncOf(pressRender))
    select {} // keep the Go program alive so the export stays callable
}
func pressRender(this js.Value, args []js.Value) any {
    req := args[0].String()               // JSON request string from JS
    resp := core.RenderJSON([]byte(req))  // the SAME seam as the cgo shim
    return string(resp)                    // JSON response string to JS
}
```
</codebase_examples>

<anti_patterns>
- Do NOT use TinyGo. Standard Go is the resolved decision (RESEARCH §3 / STATE.md decision gate). TinyGo's own 2026-04 table lists encoding/json as importable-but-not-test-passing and tracks NONE of chroma/latex2mathml/tdewolff/bluemonday. Note TinyGo as a documented future size-optimization spike ONLY (in the SUMMARY), never plan it.
- Do NOT reference `$GOROOT/misc/wasm/wasm_exec.js` — it moved to `lib/wasm/` in Go 1.24 (RESEARCH State of the Art). Use `$(go env GOROOT)/lib/wasm/wasm_exec.js`.
- Do NOT re-implement the JSON marshalling in the wasm shim — import bind/capi/core and call RenderJSON, so the web and native boundaries stay identical.
- Do NOT ship press.wasm and wasm_exec.js from different build steps/caches without the version check — a mismatch fails silently at runtime with "undefined function" (RESEARCH Pitfall 2).
- Do NOT let main() return — without `select{}` (or a channel block) the Go program exits and the registered pressRender is torn down.
</anti_patterns>

<error_recovery>

- If smoke.mjs errors "pressRender is not a function": the Go program exited (missing select{} in main) OR wasm_exec.js is the wrong version — run check-wasm-exec-version.sh first.
- If Node is missing on the runner: the smoke is the boundary gate; record which Node version the smoke expects (Node is present on this host — `node` on PATH).
