# Objective 05.1 TRD 01: eden-press-export standalone binary + chromedp gate re-scope Summary

## Accomplishments

- `cmd/eden-press-export` (standalone `package main`, no import of `cmd/eden-press`): `main.go` builds the cobra root (`Use: "eden-press-export [flags] <deck.md|->"`, `Args: cobra.MaximumNArgs(1)`), the exit-code sink (`0` ok / `1` render / `2` usage / `3` no-Chrome), and `runExport`'s pipeline; `output.go` holds the duplicated `resolveInput`, `buildPressOptions` (1:1 flag -> `press.Options` map, no koanf), `browserPath`, `stemFor`, the pure `pngOutputPath` helper, and `writePDF`/`writePNGs`.
- Pipeline verified exactly per the TRD: `resolveInput` -> `buildPressOptions` -> `press.Render` -> pre-flight `chrome.Discover(chrome.DiscoverOptions{BrowserPath: bp})` (miss -> `chromeUnavailableError`, exit 3) -> `chrome.New(convert.Options{BrowserPath: bp})` -> `pdf.ToPDF`/`png.ToImages` -> file write.
- `--inline-svg` wired to BOTH `press.Options.InlineSVG` (via `buildPressOptions`) AND `png.Options.InlineSVG` (via `opts.InlineSVG` reused, not re-read) inside the `png` case of `runExport`'s format switch -- the single load-bearing wiring seam the TRD calls out.
- Output convention: `--format pdf` writes one file to `-o` (falling back to `<stem>.pdf` for a file input with no `-o`; stdin + no `-o` is a usage error, exit 2). `--format png` writes `<stem>-001.png ... <stem>-NNN.png` into the `-o` directory (created via `MkdirAll` if missing; `""` -> CWD), or, when `-o` contains a printf integer verb, via `fmt.Sprintf(pattern, n)` per slide -- `pngOutputPath` is a pure, directly unit-tested helper for both branches.
- `scripts/check-no-chromedp.sh` re-scoped: `TREES`'s `./cmd/...` entry is now `./cmd/eden-press/...`; the core scan (press/chase/profiles/bind/cmd-eden-press) still passes with 0 chromedp. An appended block asserts `cmd/eden-press-export` builds, its own transitive closure DOES contain chromedp (a positive check), and enumerates every `./cmd/...` package to confirm `eden-press-export` is the ONLY one whose closure contains chromedp. `scripts/check-cli-imports.sh` is byte-for-byte unchanged (confirmed via `git diff`) and still PASSes.
- Test list cases 1-5 (flag surface, `resolveInput`, `buildPressOptions` incl. zero-value pass-through, `pngOutputPath` both branches, `chromeUnavailableError`) are structural and run everywhere; case 6 (live end-to-end PDF + PNG over a hand-built 3-slide deck with one math slide) is `chrome.Discover`-SKIP-guarded and correctly SKIPped in this sandbox (no system Chrome).

## Decisions Made
- Chrome discovery is checked twice on purpose (`chrome.Discover` pre-flight, then `chrome.New`'s own internal `Discover`) so a missing Chrome is reported with this binary's own clean, actionable exit-3 message rather than an opaque error from a real launch attempt.
- `--inline-svg`'s single flag value is read once (`opts.InlineSVG` from `buildPressOptions`) and threaded to both `press.Render` and `png.ToImages` from that one variable, never re-read from cobra flags a second time, structurally preventing the split-value screenshot bug the TRD warns about.
- `scripts/check-no-chromedp.sh`'s new assertion block is intentionally a POSITIVE check (closure DOES contain chromedp) in addition to the boundary check (no OTHER cmd does) -- a pure negative check alone would not catch a future accidental de-wiring of the exporter's own Chrome dependency.
