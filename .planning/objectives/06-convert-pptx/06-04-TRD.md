<objective>
Turn the docmodel into a real, editable presentation: map `chase/model.Section` → slide, `Section.Blocks` + `Outline` → editable `<p:sp>` text-box shapes with actual text runs, and expose the public `ToPPTX(model.Document, Options) ([]byte, error)`. This is where EXP-03's core promise is delivered — "editable text boxes… not a screenshot per slide" — consuming `press.Output.Model` directly with no Chrome and no HTML parsing.

Purpose: 06-01 gave us `Section.Blocks` (paragraphs, lists, headings — the editable body text that title-only decks lacked); 06-02 gave us EMU placement + the grouped-shape transform; 06-03 gave us a proven-openable deterministic package scaffold with a trivial slide. This TRD replaces that trivial slide with N model-driven slides full of real `<a:t>` runs, satisfying OBJECTIVE.md criteria 1 (from chase/model, no chromedp), 2 (editable shapes), and 3 (EMU-placed, with a grouped-shape case). It is the objective's public surface.

Output: `shapes.go` (Block→<p:sp>/<p:grpSp> builders), `slide.go` (Section→slideN.xml), `pptx.go` (public `ToPPTX` + `Options`).
</objective>

<codebase_examples>
This TRD consumes three prior deliverables in the SAME package:
- 06-01: `model.Document{Sections []Section, Outline []OutlineEntry}`; `Section{ID, Attrs, Notes, Blocks []Block}`; `Block{Kind, Text, Level, Language, Display, Ordered, Items []ListItem}`; `OutlineEntry{SectionID, Level, Text, Slug}`. Title = the Outline entry for this Section with the LOWEST Level; body = the Section's Blocks in order.
- 06-02: `Inches`/`Points`→EMU, `SlideSize16x9`/`SlideSize4x3`, the chOff/chExt identity transform.
- 06-03: the deterministic packager + static part builders (parts_static.go) + the structural asserter (openable_test.go helpers) — reuse them; only slide1.xml (hardcoded) is replaced by the model-driven slide loop.

Target `<p:sp>` text-box shape (06-RESEARCH Pattern 2 — literal target XML):
```xml
<p:sp>
  <p:nvSpPr><p:cNvPr id="2" name="Title 1"/><p:cNvSpPr txBox="1"/><p:nvPr/></p:nvSpPr>
  <p:spPr>
    <a:xfrm><a:off x="838200" y="365760"/><a:ext cx="7772400" cy="1143000"/></a:xfrm>
    <a:prstGeom prst="rect"><a:avLst/></a:prstGeom>
  </p:spPr>
  <p:txBody>
    <a:bodyPr/><a:lstStyle/>
    <a:p><a:r><a:rPr lang="en-US" sz="4400" b="1"/><a:t>Heading text</a:t></a:r></a:p>
  </p:txBody>
</p:sp>
```
List paragraphs: `<a:p>` begins with `<a:pPr lvl="N" marL="…" indent="…"><a:buChar char="•"/></a:pPr>` (bullet) or `<a:buAutoNum type="arabicPeriod"/>` (ordered) before the `<a:r>`. `lvl` = ListItem.Level.

Grouped-shape target (06-RESEARCH Pattern 4, IDENTITY v1): `<p:grpSp><p:grpSpPr><a:xfrm><a:off/><a:ext/><a:chOff/><a:chExt/></a:xfrm></p:grpSpPr> …child <p:sp>… </p:grpSp>` with chOff==off, chExt==ext (child off/ext are literal slide EMU — 06-02's identity transform).

Font size: `sz` is CENTIPOINTS (44pt ⇒ sz="4400") — use 06-02's Centipoints helper, NOT EMU.
</codebase_examples>

<anti_patterns>
- Do NOT render or parse HTML, and do NOT invoke any browser/chromedp. ToPPTX consumes `model.Document` fields ONLY (criterion 1). The whole point vs. Objective 5 is Chrome-free, structured-data-sourced export.
- Do NOT emit an image/screenshot per slide. Every text element is a real `<p:sp>` with `<a:t>` runs (criterion 2). A picture-per-slide would fail the objective outright.
- Do NOT build unescaped XML by naive string concatenation of user text. Titles/paragraphs/list items are user content — escape via `xml.EscapeText` or `encoding/xml` struct marshaling (06-RESEARCH escaping trap). Boilerplate (06-03) had no user text; slide content does.
- Do NOT emit a non-identity chOff/chExt group yet — use 06-02's IDENTITY case (Pitfall 1: prove identity in both viewers first). One grpSp case satisfies criterion 3.
- Do NOT re-implement the packager or static parts — reuse 06-03's. Only the slide loop + presentation.xml sldIdLst/rels/content-types wiring for N slides is new here.
- Do NOT break determinism — thread everything through 06-03's fixed-timestamp/zip.Store packager; never introduce time.Now() or map-ordered emission.
</anti_patterns>

<error_recovery>
- If a Section has NO Outline heading (untitled slide): emit the body shapes without a title shape (do not fabricate a title). Test this edge.
- If a Section has multiple headings: lowest Level = title shape; additional headings = heading-block text-box shapes or body lines (lock via the Test list). Do not silently drop extra headings.
- If the structural asserter (06-03) fails after adding N slides: presentation.xml's sldIdLst rIds, presentation.xml.rels, and content-types Overrides must all gain an entry PER slide — a common bug is adding the slide part + rels but forgetting the content-type Override or the sldIdLst entry.
- Escaping regressions (a `<` in a title breaks the XML): route ALL user text through xml.EscapeText/struct marshaling; add a test with `<`, `&`, `"` in a title and a paragraph.
</error_recovery>

## Test list

Write the test list FIRST, then drive each case RED → GREEN (one at a time; hand-built INLINE model fixtures — no generated test data, no property-based, no gherkin). Outermost (end-to-end ToPPTX) → innermost (single shape).

1. **Title text-box shape:** an Outline heading → a `<p:sp>` whose `<a:t>` contains the heading text, placed at expected EMU xfrm (assert exact off/ext), sz in centipoints. Real editable run, not an image.
2. **Paragraph body run:** a paragraph Block → a `<p:sp>`/`<a:p>`/`<a:r>`/`<a:t>` with the paragraph's plain text.
3. **List shape (bullet + ordered):** an unordered list Block → `<a:p>` with `<a:pPr lvl>…<a:buChar>` per item at its nesting Level; an ordered list → `<a:buAutoNum type="arabicPeriod"/>`.
4. **Grouped shape (identity):** a `<p:grpSp>` with chOff==off, chExt==ext wrapping a child `<p:sp>`, child off/ext = literal slide EMU (06-02 identity) — the criterion-3 grouped case, EMU-asserted.
5. **XML escaping:** a title and a paragraph containing `<`, `&`, `"` produce well-formed XML (`&lt;`/`&amp;`/`&quot;`) — parse the emitted slide XML to prove no corruption.
6. **Section → slide:** a 3-Section model → 3 ppt/slides/slideN.xml; each slide's shapes carry that section's title + block text; presentation.xml sldIdLst + rels + content-types each gain 3 entries.
7. **Untitled section edge:** a Section with blocks but no Outline heading → body shapes, no title shape (no fabricated title).
8. **End-to-end ToPPTX (outermost):** an inline `model.Document` fixture → `ToPPTX(doc, Options{SlideSize: SlideSize16x9})` returns a valid zip that passes 06-03's structural asserter with N slides of editable shapes; the same fixture at `SlideSize4x3` sets `<p:sldSz>` accordingly; output is deterministic (byte-identical rebuild).
