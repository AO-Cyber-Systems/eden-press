<objective>
Prove the hard part FIRST: that a hand-assembled OPC ZIP of static OOXML parts actually opens as a valid, editable presentation — on a trivial single-slide deck, before any model content, EMU-heavy layout, notes, or grouped shapes exist. 06-RESEARCH is explicit: "Sequence the TRDs static-deck-first (prove openability end-to-end on a trivial fixture before adding EMU utilities, notes, and grouped shapes)." This TRD delivers the deterministic zip packager, the complete minimal part graph, and the two schema-cardinality traps done right (12-attr clrMap, 3-entry fmtScheme lists), then a structural openability asserter that runs in CI with no PowerPoint.

Purpose: OPC has enough interlocking required-attribute traps (06-RESEARCH "Don't Hand-Roll" / Pitfalls 2-3) that most hand-rolled OOXML writers lose the most time re-deriving the part shape under deadline. By taking the part graph directly from the spec dissection in 06-RESEARCH Pattern 1 and proving it on a trivial deck now, 06-04's real content mapping becomes "fill known-good slots" rather than "debug packaging + content at once." Determinism (fixed timestamps, zip.Store, stable ordering) is baked in from the first byte so golden-hash tests are stable across machines/Go versions (Pitfall 4).

Output: `package.go` (deterministic zip), `contenttypes.go`, `parts_static.go` (the boilerplate parts), and a structural `openable_test.go` gate proving a trivial deck opens at 16:9 AND 4:3.
</objective>

<anti_patterns>
- Do NOT skip presProps.xml / viewProps.xml / tableStyles.xml / docProps/* as "PowerPoint opens without them." PowerPoint's silent-repair hides the gap; LibreOffice/stricter consumers reject it. Emit the full set now (06-RESEARCH anti-pattern: "boring parts trap").
- Do NOT range over a Go map when adding zip entries or content-type overrides — ordering must be deterministic. Use an explicit ordered slice.
- Do NOT use zip.Deflate for any test that asserts exact bytes/hash. Use zip.Store (Pitfall 4). Deflate is a later, optional size optimization only.
- Do NOT emit a partial clrMap or a variable-length fmtScheme list. All 12 clrMap attrs; exactly 3 entries per fmtScheme list.
- Do NOT depend on the model here — this TRD's slide1.xml is a hardcoded trivial title box. Model→slides mapping is 06-04. Keeping content out proves PACKAGING in isolation.
- Do NOT run `go mod tidy`. archive/zip + encoding/xml (+ optional text/template) are stdlib — no new deps.
</anti_patterns>

<error_recovery>
- If the structural asserter finds an unresolved r:id: a relationship target part was declared in a .rels but not added to the zip (or vice-versa). The part graph must be internally closed — every r:id → a rel → a target part that EXISTS and has a content-type Override/Default.
- If a golden-hash determinism test flakes across runs: a non-fixed Modified timestamp or a map-ordered part list leaked in. Pin Modified; make ALL ordering explicit.
- If LibreOffice-headless (optional smoke) hangs in parallel: a shared user-profile lock — pass a unique `-env:UserInstallation=file:///<tmp-unique>` per invocation (06-RESEARCH anti-pattern). Guard the whole soffice step behind a "soffice on PATH" check and SKIP (t.Skip) when absent, so CI without LibreOffice still passes on the structural asserts alone.
</error_recovery>

## Test list

Write the test list FIRST, then drive each case RED → GREEN (one at a time; hand-built INLINE fixtures + golden bytes in testdata/ — no generated test data, no property-based, no gherkin). Outermost (whole-deck openability) → innermost (single part cardinality).

1. **Determinism (outermost byte contract):** building the same trivial deck twice yields byte-identical zip output (fixed Modified, zip.Store, stable ordering) — a hash-equality test.
2. **Content-types coverage:** every part added to the zip has a matching Default (by extension) or Override (by part) in [Content_Types].xml; no orphan part, no override for a missing part.
3. **Relationship-graph closure:** every r:id referenced in presentation.xml/master/layout/slide rels resolves to a relationship whose Target part EXISTS in the zip (unzip + parse each .rels).
4. **clrMap 12 attributes:** slideMaster1.xml's <p:clrMap> has all 12 required attrs with the canonical identity values (Pitfall 2).
5. **fmtScheme 3-entry cardinality:** theme1.xml's fillStyleLst/lnStyleLst/effectStyleLst/bgFillStyleLst each have EXACTLY 3 children (Pitfall 3).
6. **Trivial-deck openability, 16:9:** the generated deck's presentation.xml <p:sldSz> == SlideSize16x9 (12192000×6858000, type screen16x9); slide1.xml contains one <p:sp> with an <a:t> title run; the structural asserter passes.
7. **Trivial-deck openability, 4:3:** the same build with SlideSize4x3 → <p:sldSz> == (9144000×6858000, type screen4x3); structural asserter passes — proving both aspect ratios (criterion 4) on the static deck.
8. **(Optional, skipped when soffice absent) LibreOffice-headless smoke:** `soffice --headless --convert-to pdf` on the trivial deck with a unique UserInstallation exits 0 — an independent-consumer open proof.
