The EMU facts to encode (06-RESEARCH Pattern 3, all HIGH confidence — hardcode as named constants, never recompute):
```
1 inch      = 914400 EMU
1 point     = 12700  EMU
1 centimeter= 360000 EMU
1 millimeter= 36000  EMU
Font size (a:rPr/@sz) is in CENTIPOINTS, not EMU: 44pt => sz="4400".

Slide sizes (<p:sldSz cx cy type>):
  16:9 widescreen: cx=12192000 cy=6858000  type="screen16x9"  (13.333in × 7.5in)
  4:3  standard  : cx=9144000  cy=6858000  type="screen4x3"   (10in × 7.5in)
Notes size (<p:notesSz>): cx=6858000 cy=9144000  (portrait)
```

The chOff/chExt child→slide transform (06-RESEARCH Pattern 4):
```
scaleX  = ext.cx  / chExt.cx
scaleY  = ext.cy  / chExt.cy
slideX  = off.x + (child.off.x - chOff.x) * scaleX
slideY  = off.y + (child.off.y - chOff.y) * scaleY
slideCX = child.ext.cx * scaleX
slideCY = child.ext.cy * scaleY
```
The v1 IDENTITY simplification: chOff == off and chExt == ext ⇒ scale 1, translate 0 ⇒ a child's off/ext ARE literal slide-EMU coords (06-RESEARCH Pattern 4 recommended v1). Provide both the general transform and a documented identity constructor/helper.
</codebase_examples>

<anti_patterns>
- Do NOT introduce float rounding drift into EMU values that must be exact integers. EMU is an integer unit; use int64. `Inches(x)` for a whole-inch input must be exact (1in ⇒ 914400, not 914399). For fractional inputs, define and TEST the rounding rule (round-to-nearest) so it is deterministic.
- Do NOT confuse centipoints and EMU for font size. `sz` is centipoints; positions/extents are EMU. Keep them in separate, clearly-named helpers.
- Do NOT emit non-identity chOff/chExt scaling anywhere yet — this TRD only PROVES the formula. 06-04 uses the identity case for its first grouped shape (Pitfall 1: prove identity in both viewers before scaling).

## Test list

Write the test list FIRST, then drive each case RED → GREEN (one at a time; hand-built INLINE table fixtures — no generated test data, no property-based, no gherkin). Outermost (slide-size composition) → innermost (single-unit conversion).

1. **Inch conversion:** `Inches(1) == 914400`; `Inches(10) == 9144000`; `Inches(13.333…)`→ documented value; `Inches(7.5) == 6858000` (exact).
2. **Point conversion:** `Points(1) == 12700`; `Points(72) == 914400` (72pt = 1in cross-check).
3. **Centimeter / millimeter:** `Centimeters(1) == 360000`; `Millimeters(1) == 36000`.
4. **Font-size centipoints:** the sz helper returns `4400` for 44pt (centipoints, NOT EMU) — a guard test documenting the unit distinction.
5. **Slide-size constants:** 16:9 == (12192000, 6858000, "screen16x9"); 4:3 == (9144000, 6858000, "screen4x3"); notes == (6858000, 9144000). Cross-check each against Inches (e.g. 16:9 cx == Inches(13.333…) within the documented rule; cy == Inches(7.5) exactly).
6. **Group transform — identity case:** chOff==off, chExt==ext ⇒ a child at (off.x, off.y, ext) maps to slide coords equal to its own off/ext (scale 1, translate 0). This is the criterion-3 grouped-shape case, proven here.
7. **Group transform — non-identity case:** a group with chExt = 2×ext (scale 0.5) maps a child correctly per the formula (scaleX = ext.cx/chExt.cx, slideX = off.x + (child.off.x - chOff.x)*scaleX, slideCX = child.ext.cx*scaleX) — locking the formula for a future non-identity TRD.
