<objective>

This is the objective's acceptance capstone.

Purpose: 06-04 delivered editable slides from the model; notes are the remaining docmodel content (`Section.Notes`, already populated since Objective 2) not yet exported. Wiring notes exercises the trickiest relationship-graph corner (slide → notesSlide → notesMaster → theme, plus notesMaster in presentation rels), so it is done last on a proven-good slide writer. The verification task then runs a realistic deck (titles, paragraphs, lists, notes) through the public `ToPPTX` and asserts — structurally and (optionally) via LibreOffice — that it is a valid, editable, correctly-positioned presentation at both aspect ratios: the direct evidence for criteria 1, 2, and 4.

Output: `notes.go` (Section.Notes → notesSlideN.xml + notesMaster wiring), the notes hookup in `pptx.go`'s ToPPTX, and `verify_test.go` (the comprehensive both-aspect-ratio acceptance gate).
</objective>

Notes wiring (06-RESEARCH Pattern 1 — the parts + rels a notes deck adds):
```
ppt/notesMasters/notesMaster1.xml                (+ _rels → theme1)          [once, if ANY slide has notes]
ppt/notesSlides/notesSlideN.xml                  (+ _rels → slideN + notesMaster1)   [per slide with notes]
[Content_Types].xml   += Override notesMaster + Override each notesSlideN
ppt/_rels/presentation.xml.rels  += notesMaster rId
ppt/slides/_rels/slideN.xml.rels += notesSlideN rId   (only for slides that have notes)
presentation.xml  <p:notesSz>  (already set via 06-02 NotesSize in 06-03)
```

<anti_patterns>
- Do NOT emit notesMaster/notesSlide parts for a deck (or slide) with no notes. Notes parts are conditional — an empty notesSlide with a dangling rel is a validity risk. Only slides with `len(Section.Notes) > 0` get a notesSlideN; notesMaster1 appears once iff ANY slide has notes.
- Do NOT forget the FULL wiring per notes slide: notesSlideN.xml.rels → slideN + notesMaster1, slideN.xml.rels → notesSlideN, content-types Override for the notesSlide, and (once) notesMaster Override + presentation-rels notesMaster rId. A partial wiring = unresolved r:id.
- Do NOT introduce a browser, HTML parse, or new dependency. stdlib only; Section.Notes is plain strings.
- Do NOT make the CI gate depend on LibreOffice. The structural asserter is the mandatory gate; the soffice convert is an OPTIONAL, SKIP-guarded smoke (unique UserInstallation per run — no shared-profile lock).
- Do NOT break determinism — conditional notes emission must still be in fixed order (e.g. notes parts appended in slide order), never map-ranged.
</anti_patterns>

<error_recovery>
- If the structural asserter reports an unresolved r:id after adding notes: trace slideN.xml.rels → notesSlideN (exists?), notesSlideN.xml.rels → slideN + notesMaster1 (both exist?), presentation.xml.rels → notesMaster1 (present once?), and content-types Overrides for notesMaster + every notesSlide. All must be closed.
- If LibreOffice "repairs" a notes deck that passed the structural asserter: the notesMaster or notesSlide content-type Override is likely missing, or a notesSlide references a notesMaster rId that isn't in ITS rels. Re-check the notes rels chain specifically.
- If soffice hangs in parallel test runs: shared user-profile lock — ensure each invocation gets a unique `-env:UserInstallation=file:///<tmp-unique>`; keep the step behind a PATH check + t.Skip.
- If a position assertion is brittle: assert the EMU values the writer INTENDS (from 06-02 conversions of the writer's own layout constants), not hand-guessed pixels — the contract is "positions match the writer's declared EMU layout," verified deterministically.
</error_recovery>

## Test list

Write the test list FIRST, then drive each case RED → GREEN (one at a time; hand-built INLINE model fixtures — no generated test data, no property-based, no gherkin). Outermost (whole-deck acceptance) → innermost (single notes slide).

1. **Notes slide body:** a Section with Notes `["first note","second"]` → notesSlideN.xml with two `<a:p>` runs carrying the (escaped) note text in a `<p:ph type="body">` shape.
2. **Notes wiring closure:** a deck with notes → notesMaster1.xml + rels(→theme1) present once; each notes slide's rels → slideN + notesMaster1; slideN.xml.rels → notesSlideN; content-types Override for notesMaster + each notesSlide; presentation.xml.rels has the notesMaster rId. The structural asserter passes with notes present.
3. **Conditional emission:** a deck where only slide 2 has notes → exactly one notesSlide (for slide 2), notesMaster present; slides 1 & 3 have NO notesSlide rel. A deck with zero notes → no notesMaster, no notesSlides.
4. **Comprehensive openability, 16:9 (acceptance):** a real fixture (3 sections: titles, paragraphs, a nested list, notes on ≥1) → ToPPTX at 16:9 → structural asserter passes; editable `<a:t>` runs present per slide; notesSlide bodies carry the notes; shape EMU positions match the writer's declared layout; `<p:sldSz>` == SlideSize16x9.
5. **Comprehensive openability, 4:3 (acceptance):** the SAME fixture at SlideSize4x3 → `<p:sldSz>` == SlideSize4x3; all of case 4's asserts hold — criterion 4 on both aspect ratios.
6. **(Optional, skipped when soffice absent) independent-consumer open:** LibreOffice-headless converts both the 16:9 and 4:3 decks to PDF (unique UserInstallation each) exiting 0 — PowerPoint-free open proof.
