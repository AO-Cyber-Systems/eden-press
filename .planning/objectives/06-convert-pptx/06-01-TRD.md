<objective>
Enrich `chase/model` with per-section BLOCK CONTENT (schema v2) so downstream data sinks can render real, structured document body — not just outline + notes. This is the ADDITIVE, schema-versioned model extension the locked USER DECISION requires: today `Section{ID, Attrs, Notes}` (document.go:86) deliberately has NO body content, so a PPTX built from it could only ever be title-only. After this TRD, `Section.Blocks` carries the ordered paragraphs, lists, headings, fenced code (source + language), and math ($…$/$$…$$ raw TeX + display flag) of each slide.

Purpose: this is the SHARED PREREQUISITE for two parallel objectives. Objective 6 (this objective's PPTX writer, TRD 06-04) needs paragraph + list + heading blocks → editable text-box shapes. Objective 7's DART-04 (07-RESEARCH §5, the highest-risk item in that objective) needs RAW math TeX (for `flutter_math_fork`) and RAW code + language (for `flutter_highlighting`) as JSON-native, lossless data — neither is recoverable from `Output.HTML`'s presentation-MathML / chroma-classed spans. One `Section.Blocks` union serves BOTH; it is designed once, here, so neither objective re-opens the model. Objective 7 is BLOCKED on this TRD (it is the join point).

Output: `chase/model.Section.Blocks` + the `Block`/`BlockKind`/`ListItem` types + `SchemaVersion` bump to v2 + the additive `press/math` `MathRaw()`/`MathDisplay()` accessors + Build's walk enrichment.
</objective>

_ = ast.Walk(doc, func(n ast.Node, entering bool) (ast.WalkStatus, error) {
    switch node := n.(type) {
    case *markdown.Section:

    case *ast.Heading:

    }

})
```

Sections are nested `Document > Svg > ForeignObject > Section` (svgTransformer wraps them — build.go:70-76), so this is deliberately a FULL-tree walk with a `sectionIdx` cursor, not a shallow child scan. Block nodes are encountered while `sectionIdx >= 0` — the same guard the heading/note cases use.

goldmark AST accessors you will use (all already reachable — chase/model imports `github.com/yuin/goldmark/ast`):

// BlockKind enumerates the kinds of body-content block a Section can carry.
type BlockKind string

const (
    BlockParagraph BlockKind = "paragraph"
    BlockList      BlockKind = "list"
    BlockCode      BlockKind = "code"
    BlockMath      BlockKind = "math"
    BlockHeading   BlockKind = "heading"
)

// Block is one ordered piece of a Section's body content, materialized by the
// same read-only AST walk that builds Sections/Outline. Its zero-value fields
// are omitempty so a Section with no blocks serializes without a `blocks` key.
type Block struct {
    Kind     BlockKind  `json:"kind"`
    Text     string     `json:"text,omitempty"`     // paragraph/heading plain text; code RAW source; math RAW TeX
    Level    int        `json:"level,omitempty"`    // heading level 1-6 (heading blocks only)
    Language string     `json:"language,omitempty"` // info-string language (code blocks only)
    Display  bool       `json:"display,omitempty"`  // true = display math $$…$$ (math blocks only)
    Ordered  bool       `json:"ordered,omitempty"`  // numbered list (list blocks only)
    Items    []ListItem `json:"items,omitempty"`    // list entries (list blocks only)
}

// ListItem is one entry of a list Block, with 0-based nesting Level.
type ListItem struct {
    Text  string `json:"text"`
    Level int    `json:"level,omitempty"`
}
```
